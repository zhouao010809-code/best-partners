# 原始资料回收站与队列移出

状态：2026-09-07 用户确认可恢复删除、队列移出及仓库权限规则调整，直接实施，不再重复询问产品方向。

后续变更：用户同日明确要求在回收站彻底删除，原“不永久删除”范围由 [回收站彻底删除](../plans/2026-09-07-trash-permanent-delete.md) 扩展为单条预览确认后的永久删除；不自动清空、不连带删除的限制保留。下文记录首阶段交付。

## 已确认的行为

- 原始资料列表和详情提供“移入回收站”。先展示指定 Markdown 路径、已有知识引用与影响，确认后移走该 Markdown；目录、附件、其他原文、正式知识与提炼历史不删不改。回收站可恢复到原路径；不永久删除、不自动清空。
- 提炼队列提供“移出队列”和“已移出 → 重新加入”。仅改变本机队列安排，保留全部原文、候选、取舍和入库记录，不改来源 YAML。被移出资料不再占待处理牌堆，仍在原始资料可见。
- 正在提炼的资料先通过已有停止按钮停止。未完成入库批次先处理恢复，不能一边写入一边回收。已有模型预览在确认发送前重新检查这些状态。
- 回收后不再出现在正常原始资料、提炼队列或牌堆。还原不会自动调用模型，也不撤销此前明确的队列移出状态。
- 恢复遇到同名文件或父目录消失时不覆盖、不换名猜测，回收站保留原文件并显示具体原因。中断后可在回收站继续核验同一条操作，无重复移动。

## 界面

沿用暗色绿色与左导航。原始资料列表增加独立垃圾桶操作，工具区新增“回收站”；详情使用明确文字按钮。回收预览只有一个确认动作并列出引用知识，不弹多层审批。回收站内显示时间、原路径、状态及“恢复”或“继续核验”；可查看已恢复回执。队列使用独立已移出筛选与可撤销操作，不把移出伪装成删除提炼结果。

## 技术与数据边界

复用锁定的个人 archive root，新增独立 native trash 端口与同卷私有 `personal-trash-v1`。仅接受已归档来源目录内的 `.md` 文件；排他 rename 移入 UUID 槽和恢复，禁止覆盖、软硬链接及越界。移动前持久化不可变意图与 SQLite 状态，移动后按身份和 hash 复核，索引更新失败可独立重试。启动只核验已确认记录，不自动确认预览、不自动删除。

新增 SQLite migration 010：队列隐藏表、回收操作表；原候选与批次不删除。文件暂时移出会使 Obsidian 原路径引用失效，预览明确提示；恢复到原路径后恢复引用。不批量改写知识链接。

## 验收

独立临时库验证预览不写、显式确认才移动、字节与 inode 保留、重启恢复、同名冲突不覆盖、引用知识不变、移出队列保留历史和原始资料、重复动作幂等、旧模型预览阻断、开发与打包 App 操作及宽窄窗。真实大脑只读部署检查，不拿真实资料试删。
