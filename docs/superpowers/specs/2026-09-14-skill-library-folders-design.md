# Skill 库自定义文件夹与源文件定位：最简版设计

> 2026-09-26 更新：原先“不提供删除”的范围已调整，个人自定义文件夹新增整包可恢复回收；当前行为和验证见 [创作取舍与恢复验收](../../reviews/2026-09-26-creation-recovery.md)。下文保留原设计记录。

**日期：** 2026-09-14
**状态：** 待用户审阅；范围已确认

## 目标

在现有只读 Skill 库上增加最小的整理能力：用户可以在 Skill 库中创建一层自定义文件夹，给文件夹命名，手动把 Skill 移到目标文件夹，并从 Skill 详情直接在访达中定位源文件。

分类仍以本地文件夹为真源。应用不复制 Skill 内容，也不引入 AI 自动分类或重复清理流程。

## 用户流程

```text
打开 Skill 库
  → 点击“新建文件夹”并输入名称
  → 看到“未分类”和自定义文件夹
  → 在某个 Skill 卡片上点击“移动到…”
  → 选择目标文件夹，移动完成后列表刷新
  → 点击“在访达中打开”，定位该 Skill 的 SKILL.md
```

创建文件夹和移动 Skill 都只影响 `.claude/skills` 下的目录结构，不改写 `SKILL.md` 内容。

## 文件系统模型

当前大脑目录下的 Skill 根保持为 `.claude/skills`，只支持一层自定义分类：

```text
.claude/skills/
  wechat-publisher/SKILL.md          # 未分类 Skill
  通用/skill-a/SKILL.md              # 自定义文件夹中的 Skill
  写作/skill-b/SKILL.md
```

- 根目录下直接包含 `SKILL.md` 的子目录归入“未分类”。
- 根目录下不直接包含 `SKILL.md` 的一层子目录视为自定义文件夹；只读取其直接子目录中的 `SKILL.md`，不继续递归。
- 创建文件夹只允许安全的单层名称；不接受 `/`、反斜杠、控制字符、隐藏名或 `scripts`、`env` 等保留名。
- Skill 目录名在整个 Skill 根内保持唯一，移动时不改目录名，因此已有的 opaque `skillId` 仍然稳定；移动前若目标中已有同名目录，操作直接冲突，不覆盖也不改名。
- 移动不会覆盖同名目标；目标冲突或外部文件变化时返回明确错误并要求刷新。
- 空的自定义文件夹保留在磁盘上，便于用户先建分类再逐个归档 Skill。
- 本版本不提供删除或重命名文件夹；用户仍可在访达中自行维护，回到应用后刷新即可看到结果。

如果 `.claude/skills` 尚不存在，首次点击“新建文件夹”时可以创建 `.claude/skills` 及目标文件夹；不创建任何 Skill 文件。

## 服务与 API

沿用现有独立 Skill catalog 服务，但从“只读发现”扩展为有界的目录管理服务。服务始终由桌面端固定传入当前大脑的 `.claude/skills`，不接受 renderer 提交绝对路径。

### 列表

`GET /api/v1/skills`

返回：

```ts
{
  folders: Array<{
    id: string;          // 文件夹名称的 opaque hash
    name: string;
    skillCount: number;
  }>;
  items: Array<{
    id: string;          // 现有 Skill opaque id
    name: string;
    description: string;
    revision: string;
    folderId: string | null;
    folderName: string | null;
  }>;
}
```

`folderId: null` 表示“未分类”。列表同时返回空文件夹；排序按文件系统名称稳定排序，未分类排在自定义文件夹之前。

### 新建文件夹

`POST /api/v1/skills/folders`

请求体（`folderId` 也可以为 `null`）：

```json
{ "name": "写作" }
```

成功返回新文件夹。名称已存在、名称不安全或根目录不可写时返回可理解的错误；不会覆盖现有目录。

### 移动 Skill

`POST /api/v1/skills/:id/move`

请求体：

```json
{ "folderId": "<folder-id>" }
```

`folderId: null` 表示移回“未分类”。服务通过 `skillId` 和 `folderId` 重新解析实际目录，校验根目录、目录身份、符号链接和目标冲突后执行同卷 `rename`。移动成功返回更新后的 Skill 摘要；任何失败都不返回成功。

两个写接口沿用现有 session/CSRF 保护，仅在 `filesystem` 桌面适配器启用；`local-rest` 连接继续返回 Skill catalog unavailable。

## 访达定位

新增桌面 bridge 方法 `revealSkill(skillId)`：

1. renderer 只发送 opaque `skillId`，不发送路径；
2. Electron 主进程在固定 `.claude/skills` 根内解析该 ID，并重新校验目录和 `SKILL.md` 是真实文件；
3. 使用 `shell.showItemInFolder(<skill-directory>/SKILL.md)`，让访达直接选中源文件；
4. 解析失败或访达调用失败只返回普通语言错误，不泄露系统路径或底层错误文本。

Skill 详情和卡片都提供“在访达中打开”。没有桌面 bridge 时隐藏该按钮，并保留当前只读正文和相对目录信息。

## 页面交互

- Skill 库顶部显示“新建文件夹”按钮和现有文件夹列表；“未分类”是固定入口，不可删除。
- 新建时使用行内输入框：提交前只检查名称，成功后回到列表并选中新文件夹；取消不改文件。
- 卡片保留“查看方法”，新增“移动到…”按钮/菜单。菜单只列出已有自定义文件夹和“未分类”，点击即执行一次移动并刷新列表。
- 移动期间按钮禁用，成功显示短暂状态提示，失败在当前卡片附近显示原因和“重试/刷新”。
- 详情页新增“在访达中打开”；请求中显示“正在打开…”，失败可再次点击。
- 页面继续标注 Skill 正文为只读；不增加编辑器、执行按钮或 AI 推荐按钮。

## 错误与外部变化

- 根目录不存在或无权限：列表沿用现有不可用状态；新建/移动显示“Skill 文件夹暂时无法写入，请检查当前大脑文件夹权限”。
- 名称为空、过长、含路径分隔符或保留名：不发请求，在输入框旁提示修正规则。
- 文件夹已存在：保留用户输入，提示“这个文件夹已经存在”。
- Skill 在操作前后被访达或其他程序移动：服务拒绝猜测，提示刷新 Skill 库；不创建副本、不覆盖目标。
- 目录中存在更深层嵌套或不含 `SKILL.md` 的文件夹：不作为 Skill 展示，也不被移动；刷新后仍留在原处。

## 安全与权限边界

- 所有读写都锚定并重新校验 canonical `.claude/skills` 根；拒绝符号链接、根替换、绝对路径和 `..`。
- 只操作目录创建和 Skill 目录移动，不读取或写入 `scripts/`、`.env*`、密钥或其他任意文件。
- 移动不改 `SKILL.md` 字节、frontmatter、引用文件或 Skill 目录名。
- 不提供删除能力；用户在访达中的删除不由应用拦截，应用只在下一次刷新时反映现状。

## 测试与验收

### 服务与 API

- 单元测试覆盖：根目录未分类发现、一层文件夹发现、空文件夹、创建安全名称、非法名称、重复名称、移动到文件夹、移回未分类、同名冲突、符号链接和外部变更。
- 集成测试覆盖：列表返回文件夹与归属、创建/移动需要 CSRF、成功响应、错误响应及未配置 catalog 的 503。

### Electron 与页面

- 原生导航测试覆盖：合法 `skillId` 只调用 `showItemInFolder` 指向真实 `SKILL.md`；无效 ID、符号链接、根替换和 Finder 失败不调用或不泄露路径。
- 组件测试覆盖：新建文件夹输入、取消/成功/重复错误、移动菜单、刷新后的归属、访达按钮成功/失败，以及无 bridge 时的降级。
- 手动隔离验收：建立四个测试 Skill，创建两个文件夹，把 Skill 分别移动进去，刷新后归属保持；点击访达按钮能选中对应 `SKILL.md`。

## 明确不在本版本

- AI 自动分类、自动执行或自动串联 Skill；
- 重复检测、删除、回收站和批量清理；
- 文件夹删除、重命名、嵌套多级分类；
- App 内编辑 Skill 内容；
- 问问调用链路和发布、音频、视频工作流。

## 完成判据

1. 用户能在 Skill 库中创建一个自定义命名文件夹，且实际目录出现在 `.claude/skills` 下。
2. 用户能通过点击“移动到…”把任一现有 Skill 放入或移出该文件夹，源文件内容不变。
3. 刷新后文件夹、Skill 归属和空文件夹状态与磁盘一致。
4. 用户能从卡片或详情一键在访达中定位该 Skill 的 `SKILL.md`。
5. 不支持的路径、符号链接、写入失败和外部冲突都有明确反馈，且不误报成功。
