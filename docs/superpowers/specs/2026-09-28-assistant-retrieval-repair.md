# 问问检索修复

用户已确认修复诊断出的检索链路问题。目标是已有可读资料能被正确召回和读取，并让实际搜索范围与界面一致。

## 行为

- 从项目进入 Skill 库浏览方法时保留同一项目问问；进入其他全局页面时离开项目范围。项目内新建对话从创建草稿开始就绑定当前项目和版本，不生成全局草稿。
- 全局知识继续只搜索标题及 YAML 召回字段，原始资料继续只搜标题；项目继续只搜当前项目路径及已解析正文。默认过时、回收站与跨项目隔离不变。
- 关键词按空格和中文词边界拆分，所有词均需命中；直接标题/文件名匹配优先。包含标点的原有查询保持可匹配。搜索分页按稳定相关性顺序续接，普通浏览仍按路径续接。
- 项目读取接受搜索返回的同项目 `project:<id>/<relativePath>` 和原相对路径，拒绝其他项目引用、绝对路径及穿越。编辑提案仍只接受相对路径。
- 工具区分本次匹配数量、返回数量与项目总量。模型获得项目文件总量、可读量，明确空结果不是全库不存在；短词重试和正确项目工具是取证的一部分。

## 边界

本次不新增向量服务或模型请求，不修改原始资料和知识字段规则。中文拆词是本地关键词召回，不承诺任意口语句的语义理解。DOCX/XLSX/HTML/RAR 等解析扩展独立处理；当前返回的不可解析状态必须与文件不存在区分。

## 验证

先用隔离索引复现分散关键词、中文词序、相关性排序分页、搜索路径无法直接读取及项目导航丢范围，再最小修复。回归包含跨项目、来源字段/正文排除、过时过滤、标点保真和草稿隔离。桌面验收使用临时大脑/项目/userData，模型发送被拦截；运行首次使用与项目导航开发/打包测试后再更新本机 App。
