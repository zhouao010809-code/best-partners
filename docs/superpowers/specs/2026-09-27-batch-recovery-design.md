# 项目与 Skill 分类的批量回收

## 用户问题

0.1.7 补上了单条回收和恢复，却仍要求用户逐条操作，整理一批不需要的创作或分类十分费力。本次在已有项目选题、脚本、已定稿及个人 Skill 分类的回收流程上补齐多选闭环。

## 交互约定

- 列表中直接提供有可访问名称的复选框；点击复选框不打开内容或改变当前分类。
- 工具条显示已选数量、全选或取消全选，以及带数量的批量操作。全选只选当前列表中可操作的条目，不包含隐藏视图或未分类根目录。
- 项目切换、列表视图切换清除选择；数据刷新剔除不再可操作的选择。空选择不能提交。
- 批量回收只弹一次确认，列出具体标题/文件夹名、数量和影响；长列表可滚动。取消不修改资料并保留选择。
- Skill 必须先完成每个选中文件夹的现有安全预览，确认所见范围后才能回收。预览失败或过期要明确提示重新核对。
- 处理期间显示进度，锁定重复提交及会丢失当前结果的局部操作。
- 逐条调用现有回收/恢复接口，保留修订号、目录身份、同名冲突等校验。不增加绕过保护的路径。
- 成功项移出当前列表；失败项保留选择并显示具体原因。中断或结果未知时提示刷新核对，不能误报整批成功。
- 本次成功回收的条目可整批撤销；回收站可多选恢复。撤销/恢复冲突保留条目并说明原因，不覆盖其他修改。
- 重启后从回收站恢复沿用已有持久化记录；项目正文、版本与讨论、Skill 隐藏文件一并保留。

## 实施与验证

两个独立界面分别维护选择和批量结果，复用已有单条服务；需要时提取局部组件，避免扩大通用架构。新增组件回归覆盖选择范围、取消、重复操作、部分失败、整批撤销与恢复。Electron 使用隔离资料验证开发版和打包版的批量闭环、重启恢复、保留未选项和原文件字节，并查看宽窄窗口截图。核心写入入口复跑首次使用走查。

完成后运行相应验证、构建 0.1.8、同步 GitHub 发布并更新本机应用；不在用户真实资料中试删。真实付费 AI 不属于此项验收。

## 范围

本次对应用户上一轮指出的 Skill 自定义文件夹和项目创作条目；统一资料回收站的永久删除仍遵守原有单独确认规则。对项目绑定、项目源文件、公司 Skill 和全局 Skill 不扩展删除能力。
