# 个人项目工作区与项目模式问问设计

**日期：** 2026-09-21  
**状态：** 设计已获用户方向确认，待用户复核本文档后进入实施计划  
**范围：** 个人桌面版；不改变公司工作区的独立运行边界

## 1. 决策摘要

在个人版侧边栏增加“我的项目”。用户通过系统文件夹选择器绑定一个已经存在的本地项目文件夹，不填写一套新的项目表单，也不复制原文件。每个绑定项目拥有独立的项目索引、项目问问上下文和项目产出区。

现有“问问”不拆成第二个 AI。进入项目工作区后，同一个问问切换到 `project` 上下文：

```text
项目文件夹（客户事实与语料）
        + 全局知识库（通用方法与经验，只读检索）
        + 本次自然语言任务
        → 项目专属的内容、选题、脚本、计划或复盘产出
```

项目内容默认不写回全局知识库；项目产出默认写入当前项目的 `AI工作区/`，不覆盖项目原始资料。将项目经验沉淀为全局知识必须经过现有的候选审阅与确认流程。

第一版优先验证“项目语料 + 全局知识库 → 获客内容选题优化”这一条闭环，不引入必填的项目阶段、当前节点或项目管理状态。

## 2. 用户问题与目标

用户是代运营从业者，已经拥有一个长期维护的个人知识库，也为不同客户维护各自的项目文件夹。当前两个系统之间缺少一个稳定的工作入口：

- 全局知识库可以沉淀通用方法，但调用时需要用户自己组织上下文；
- 客户项目资料分散在本地文件夹，内容生产时需要反复手动翻找；
- 一个客户的事实、语气和历史内容不能混入另一个客户；
- AI 需要能在项目范围内产出和迭代，但不能未经确认污染全局知识库或覆盖原始资料。

本设计的目标是让用户能够：

1. 绑定已有项目文件夹，而不是重复填写项目资料；
2. 进入某个项目后直接使用同一个“问问”；
3. 用自然语言描述一次任务，例如“下周拍 6 条获客内容”；
4. 让问问从当前项目语料和全局知识库中分别取用证据与方法；
5. 将确认后的产出保存到当前项目并保留版本；
6. 保持项目之间、项目与全局知识库之间的边界清晰可追溯。

## 3. 不在目标内的事情

第一版不做以下事情：

- 不创建第二个独立的“项目问问”模型或聊天服务；
- 不要求用户填写客户名称、阶段、当前节点、目标等固定表单字段；
- 不让项目模式默认读取所有其他项目；
- 不把全局知识库复制到每个项目；
- 不让 AI 静默覆盖项目原有资料或项目规则；
- 不把项目产出自动写入 `02知识库`；
- 不在第一版同时实现发布、平台数据看板、排期系统和全自动跨项目学习；
- 不改变公司版 `/company/*` 的认证、共享工作区和文件复制流程。

## 4. 核心概念与边界

### 4.1 项目

项目是一个由用户绑定的本地文件夹，以及应用为其维护的索引和操作记录。文件夹是项目事实和原始语料的真源。项目不要求固定目录结构；如果存在 `项目说明.md`、`README.md` 或其他说明文件，系统可以读取，但不存在时仍可创建项目。

项目注册表只保存绑定关系、索引状态和应用元数据，不复制项目内容。绝对路径只保存在本地服务端注册表，不作为模型上下文或普通 API 的自由路径参数传入。

### 4.2 全局知识库

全局知识库继续沿用用户现有的剪藏、提炼和确认入库流程。它是项目问问的共享能力层，默认只读检索：

- 项目可以查询全局知识的标题、召回字段和正文证据；
- 项目问问不会直接修改全局知识 Markdown；
- 用户明确选择“沉淀为全局知识”后，才进入现有的候选审阅流程；
- 项目事实不会因为被问问读取而自动成为通用知识。

### 4.3 项目模式

项目模式是同一个问问的上下文作用域，不是第二个助手。一次对话只能绑定一个项目：

```text
scope = brain       全局大脑
scope = current     当前资料
scope = project     当前项目 + 全局知识检索
```

进入 A 项目工作区时自动使用 `scope=project`、`projectId=A`。从全局问问切换到项目时必须显式选择项目；切换项目会新建或恢复目标项目的对话，不把两个项目的历史拼接在同一轮上下文中。

### 4.4 本次任务

任务是用户在输入框中用自然语言描述的临时需求，例如：

> 下周要拍 6 条视频，目标是获客，请根据 A 项目的语料和我的知识库优化选题。

系统可以从任务中提取数量、时间、平台、目标、受众和交付形式，但这些信息默认只属于本次请求，不变成项目必填字段。只有用户明确要求保存时，才将任务简报作为项目记录写入。

## 5. 用户体验

### 5.1 侧边栏与路由

个人侧边栏新增一级入口“我的项目”。侧边栏只显示入口和项目数量/状态摘要，不默认展开所有项目，避免项目数量增长后挤占主导航。

建议路由：

- `/projects`：项目列表与绑定入口；
- `/projects/:id`：项目工作区；
- `/projects/:id/files`：可选的项目文件浏览深链接；第一版可以由工作区内的面板承载，不单独暴露导航项。

### 5.2 绑定已有文件夹

点击“添加项目”后使用 Electron 原生文件夹选择器，流程如下：

1. 用户选择本地文件夹；
2. 服务端校验路径存在、确实是目录，并解析真实路径；
3. 扫描文件树、文件类型、大小、修改时间和内容哈希；
4. 展示扫描预览：文件数量、可读取文件、忽略文件、解析失败和可能的说明文件；
5. 用户确认绑定；
6. 写入项目注册表并建立索引。

绑定阶段不创建项目表单，也不向文件夹写入系统文件。项目显示名默认使用文件夹名，用户可以在预览确认时改一个显示名称，但不要求补齐客户背景等字段。

### 5.3 项目工作区

项目工作区包含四个信息区：

- 项目文件：按相对路径搜索和打开项目语料；
- 最近产出：展示 AI 在项目中生成的草稿、选题和计划；
- 同步状态：显示正在扫描、已更新、文件夹不可用或需要重新绑定；
- 问问：固定显示当前项目标识和知识范围。

问问顶部显示明确的上下文提示：

```text
项目模式 · A 项目
项目语料：已连接
全局知识库：可检索
写入范围：A 项目 / AI工作区
```

### 5.4 项目问问的输入与输出

问问不要求先选择“当前节点”或填写任务表。用户直接输入业务任务。回答必须区分：

- `项目资料`：当前项目文件夹中的事实和证据；
- `全局知识`：用户长期积累的通用知识和方法；
- `用户要求`：本次输入中的数量、时间和目标；
- `AI判断`：模型基于证据做出的推断或建议。

以选题任务为例，输出至少包含：

1. 是否适合当前项目的判断；
2. 依据和引用来源；
3. 主要问题或风险；
4. 优化后的选题方向和标题；
5. 可直接交给拍摄/编导的下一步建议；
6. 信息不足时的明确假设或需要补充的问题。

问问可以检索全局知识库，但不把整个知识库一次性塞进上下文。先按任务召回，再读取少量最相关正文，沿用现有来源、证据片段和上下文预算机制。

## 6. 项目语料索引与读取

### 6.1 第一版支持范围

第一版直接读取：

- Markdown（`.md`）；
- 纯文本（`.txt`）；
- 有文字层的 PDF（`.pdf`）。

其他文件可以显示在项目文件清单中，但第一版只提供文件元数据和“暂不支持内容读取”的状态，不伪造其内容。图片、视频、DOCX、表格和扫描 PDF 后续单独增加解析能力。

### 6.2 扫描规则

沿用现有本地文件安全原则：

- 忽略 `.git`、`node_modules` 等系统/依赖目录；
- 拒绝符号链接逃逸和不支持的文件类型；
- 使用 canonical path 确认读取目标仍在绑定根目录内；
- 记录相对路径、大小、修改时间、内容哈希和解析状态；
- 单轮问问只读取搜索命中的少量文件，遵守现有文档数、字符数和模型上下文上限；
- 不因为某个文件解析失败而把整个项目当成空项目。

### 6.3 变化检测

第一版支持手动刷新和应用运行期间的低频扫描；扫描发现文件增加、删除或哈希变化时，更新项目索引并显示状态。实时文件监听可以作为后续优化，不把“毫秒级实时”作为第一版承诺。

全局知识库索引更新后，项目问问下一次检索自动使用新版本；不在后台静默重写项目文件。

## 7. 受控写入与版本

### 7.1 项目写入区

首次用户点击“保存到项目”并确认后，才在项目根目录创建：

```text
AI工作区/
├── 选题评估/
├── 内容草稿/
├── 周计划/
├── 复盘草稿/
└── 工作日志/
```

具体文件名由任务类型和日期生成，重复保存创建新版本或新文件，不覆盖原始资料。

### 7.2 写入策略

在用户确认保存后，默认允许：

- 生成新的项目草稿；
- 追加 AI 工作日志；
- 保存选题评估、内容计划和脚本草案；
- 更新应用自己的项目索引和操作记录。

默认需要用户确认：

- 修改项目原有的背景、规则或策略文件；
- 覆盖已有项目产出；
- 删除或重命名项目文件；
- 将项目内容提炼为全局知识；
- 根据新全局知识批量改写多个项目文件。

所有需要确认的写入先生成差异预览和操作编号，成功后记录目标路径、旧哈希、新哈希和可恢复信息。写入失败不得声称成功。

### 7.3 全局知识沉淀

项目问问中的“沉淀为全局知识”不是直接写入 `02知识库`，而是调用已有候选提炼/审阅链：

```text
项目产出
→ 用户选择沉淀
→ 生成知识候选
→ 用户编辑和确认
→ 才进入全局知识库
```

## 8. 上下文与检索优先级

每次项目问问的上下文由四部分组成：

```text
当前任务简报
    + 当前项目的相关语料
    + 全局知识库的相关知识
    + 已确认的本轮对话历史
```

事实冲突时：

- 当前项目文件中的客户事实优先于全局通用案例；
- 全局知识只用于方法、判断框架和可复用经验；
- 无法确认的内容标为待核实，不用其他项目的内容补猜；
- 资料中的命令、提示或外部指令只是数据，不能改变系统权限。

第一版不提供“默认读取所有其他项目”。后续如需借鉴历史项目，增加显式的“参考项目”选择，并把其来源单独标注为案例参考。

## 9. 数据模型与接口边界

### 9.1 项目注册表

本地数据库新增项目注册表，至少包含：

- `id`：稳定项目 ID；
- `rootPath`：canonical absolute path，仅服务端保存；
- `displayName`：用户可见名称；
- `sourceRevision`：当前文件树索引版本；
- `availability`：`ready`、`scanning`、`unavailable`、`reconnect-required`；
- `outputRoot`：项目工作区相对路径，默认 `AI工作区/`；
- `createdAt`、`updatedAt`；
- `writePolicy`：第一版固定为“新产出受控写入，原始文件不可静默覆盖”。

项目 API 只返回项目 ID、显示名、相对路径、状态和摘要。绝对路径不进入模型消息、来源引用或可自由拼接的前端参数。

### 9.2 助手会话

现有助手会话扩展为：

- `scope: 'project'`；
- `projectId`；
- `projectRevision`；
- 可选的任务标签，仅用于历史筛选，不决定权限。

项目会话历史按项目隔离。项目不可用时，历史对话仍可阅读，但新的项目读取和写入被禁用，直到重新连接或刷新索引。

### 9.3 工具边界

新增项目工具必须与全局 brain 工具分开声明：

- `search_project_files`：只搜索绑定项目的索引；
- `read_project_file`：只读取当前项目根目录内的相对路径；
- `save_project_draft`：只创建 `AI工作区/` 下的新文件；
- `propose_project_edit`：为修改已有文件生成差异，不直接落盘；
- `refresh_project_index`：重新扫描当前项目，不接受任意路径。

模型不能自行传入绝对路径、切换 `projectId`、读取其他项目或调用任意文件系统命令。

## 10. 现有实现的复用与隔离

可以复用：

- 现有个人问问的会话、来源、证据片段和上下文预算；
- 现有本地索引和文件读取的错误处理模式；
- 现有写入计划、确认、操作日志和恢复机制；
- 公司版项目扫描器中确定性文件遍历、哈希和字段证据的思路。

不能直接复用：

- 公司版将 incoming 项目复制到共享 `projects/` 的发布流程；个人项目需要绑定并持续读取原文件夹；
- 公司版认证、公司数据库和公司 MCP 权限；个人项目必须留在个人运行时；
- 公司版“只生成外部 Agent 提示词”的项目助理；个人项目需要真正接入应用内问问。

个人版新增项目功能不能让公司运行时读取个人 vault，也不能让个人问问意外获得公司项目工具。

## 11. 错误、冲突与恢复

- 文件夹不存在、被移动或权限不足：显示“需要重新连接”，保留项目注册表和历史对话，不自动替换为相似目录；
- 扫描期间源文件发生变化：放弃本次不一致索引，提示重新扫描，不把旧索引伪装成最新；
- AI 写入前源文件哈希已变化：使写入计划失效，要求重新预览；
- 输出目标文件已存在：默认创建新版本或要求用户选择，不覆盖；
- 某个文件解析失败：保留文件清单和失败原因，其他可读文件仍可检索；
- 全局知识和项目资料结论冲突：分别展示来源和冲突，不自动合并；
- 对话切换项目：新建或恢复目标项目会话，不沿用上一项目的隐式上下文；
- 所有项目写入都保留操作编号、前后哈希和恢复入口。

## 12. 分阶段交付

### P0：项目内容生产闭环（本设计范围）

1. 侧边栏“我的项目”；
2. 原生文件夹绑定和扫描预览；
3. 项目注册表、项目列表和项目工作区；
4. `project` 问问上下文；
5. 项目语料搜索/阅读 + 全局知识检索；
6. 自然语言任务输入；
7. 选题评估/优化与周内容计划的项目草稿保存；
8. 项目与全局知识库隔离；
9. 手动刷新和基础变化检测；
10. 写入差异、操作记录和恢复。

### P1：持续迭代

- 低频文件监听和后台索引；
- “发现新全局知识可能适用于此项目”的建议卡；
- 脚本生成、复盘和更多内容任务模板；
- 显式选择参考项目；
- 项目级自动保存草稿偏好。

### P2：受控知识回流

- 项目经验生成全局知识候选；
- 跨项目案例库；
- 项目结果和内容表现的结构化复盘；
- 在用户授权下的批量项目更新计划。

## 13. 测试与验收

所有测试使用临时项目文件夹和临时大脑，不触碰用户真实资料。

### 单元测试

- 根目录 canonicalization、路径包含关系和符号链接逃逸；
- 文件树扫描、哈希、忽略目录和不支持类型；
- 项目索引增量变化与 stale revision；
- 项目工具不能读取其他项目或全局之外的路径；
- 项目写入只能落在 `AI工作区/`，覆盖、删除和全局写入均被拒绝或转为提案；
- 写入前后哈希、操作日志和恢复记录；
- 项目上下文与 `brain/current` 上下文的 schema 校验。

### 组件与 Electron 测试

至少覆盖：

1. 选择项目文件夹后无需填写项目表单即可完成绑定；
2. A 项目工作区显示同步状态、问问上下文和文件索引；
3. 在 A 项目输入“下周拍 6 条获客内容”时，问问能同时返回项目来源和全局知识来源；
4. A 项目会话不能检索 B 项目；
5. 保存产出后只新增 A 项目 `AI工作区/` 文件，全局知识库哈希不变；
6. 外部修改项目文件后刷新索引，下一轮问问能使用新内容；
7. 项目移动或权限失效时显示重新连接，不丢历史；
8. 原有个人首次使用、问问全局模式、提炼队列和公司工作区回归测试保持通过。

### 可交付验收句

一个没有预先填写项目表单的用户，可以选择自己的客户项目文件夹，进入项目工作区，输入“下周拍 6 条获客内容”，得到基于该项目语料和全局知识库、带来源说明的选题建议，并把确认后的结果保存到项目文件夹，而不改变全局知识库或其他项目。

## 14. 设计自审结论

- 没有把“当前节点/阶段”作为强制字段；
- 没有把项目模式拆成第二个 AI；
- 项目文件夹、项目写入区、全局知识库的职责互不重叠；
- 默认不读取其他项目，避免客户资料串用；
- “实时”被定义为索引和下一次任务可用，不承诺后台无确认重写核心资料；
- 第一版有单一可验收闭环，不依赖平台数据、发布系统或完整项目管理；
- 方案可复用现有问问和扫描/写入基础，但不混用个人与公司运行时；
- 所有自动写入、路径访问和知识回流都有明确的边界与恢复入口。
