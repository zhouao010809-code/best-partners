# Skill 库与问问 AI 调用闭环设计

**日期：** 2026-09-20
**状态：** 待用户审阅；基于已确认的 A 方案和“只生成聊天草稿”范围
**前置设计：** [Skill 库与问问调用入口：最小可用版设计](2026-09-14-skill-library-invocation-design.md)

## 目标

让本地 Skill 库真正服务于“问问 AI”：用户输入一个任务后，应用先在本机从 Skill 库找出最匹配的方法，展示推荐卡片；用户明确确认后，才把该 Skill 和任务交给已连接的 AI，结果留在当前对话中。

本轮只建立一个可控的单 Skill 调用闭环，不自动保存文章、不改知识库、不执行 Skill 目录中的脚本。

## 用户流程

```text
用户在问问输入任务
  → 本地匹配 Skill（不调用外部模型）
  → 对话内出现推荐卡片
  → 用户选择“使用此 Skill”或“不用”
  → 确认后才发送任务与 Skill 方法说明
  → AI 在当前对话返回文案草稿
```

### 有匹配结果

推荐卡片显示：

- Skill 名称；
- 一句话用途/匹配原因；
- 所在 Skill 文件夹；
- `使用此 Skill`、`不用`、`换一个` 三个动作。

点击 `使用此 Skill` 是唯一的外部发送确认点。卡片和回答都标明本轮实际使用的 Skill。点击 `不用` 后按普通问问发送原问题；点击 `换一个` 只展开本地匹配到的其他候选，不重新调用模型。

### 没有匹配结果

不显示误导性的推荐，直接发送普通问问；界面不声称“已经使用 Skill”。本地匹配服务暂时不可用时，不自动发送，显示“重试匹配”与“继续普通问问”两个选择。

## 匹配规则

第一版使用本地确定性匹配，不先调用 AI 做分类，避免额外费用、延迟和未经确认的外发。

- 候选来自当前大脑 `.claude/skills` 的合法 Skill 目录。
- 服务端读取 Skill 的名称、描述和受控的 `SKILL.md` 文本用于匹配；目录中的脚本、`.env`、隐藏文件和任意绝对路径不参与读取。
- 对用户任务和候选文本做统一的小写、空白和标点归一化；中文按连续词片段和完整短语匹配，英文/数字按单词边界匹配。
- 名称和描述权重高于正文触发词；只返回达到最低命中条件的候选，最多返回 3 个，分数相同按稳定的 `skillId` 顺序排列。
- 推荐结果只包含不含本机绝对路径的 `skillId`、名称、描述、文件夹名称、版本指纹和简短匹配原因。
- 匹配结果带上当时的版本指纹。用户确认时若 Skill 内容已变化，服务端拒绝使用旧推荐并要求重新匹配。

以后可以增加“本地筛选后由 AI 二次排序”，但不属于本轮。

## 架构与数据流

### 本地匹配

新增独立的 Skill matcher 服务，依赖现有 `SkillCatalogService`，不绕过 canonical root、符号链接和大小限制。新增本地 API：

```text
POST /api/v1/skills/match
{ "message": "帮我把这个选题写成公众号文章" }
→ { candidates: [{ id, name, description, folderName, revision, reason }] }
```

该接口只在本机运行，返回元数据，不返回 Skill 正文，也不访问外部网络。

### 问问发送

扩展现有 `assistantSend` 请求，使确认后的请求可以携带不透明的 `skillId` 和匹配时的 `skillRevision`。服务端收到后：

1. 用 `skillId` 在固定 Skill 根目录重新解析 Skill；
2. 校验版本指纹仍与推荐一致；
3. 读取有界的 `SKILL.md`；
4. 将内容放入明确分隔的“Skill 方法说明”上下文块；
5. 保持现有系统提示、资料检索工具和权限边界优先级；
6. 让模型只在当前对话中生成回答。

前端永远不提交文件路径，模型也不能通过 Skill 内容获得文件写入、命令执行、网络访问或发布权限。

### 对话记录

保存本轮使用的 Skill 元数据（`id`、名称、版本指纹，必要时文件夹名称），使历史对话能明确显示“本轮使用了什么”。不保存一份可编辑的 Skill 副本；Skill 真源仍是本地 `SKILL.md`。

## 发送边界与隐私提示

- 输入任务和 Skill 方法说明在点击 `使用此 Skill` 之前只留在本机。
- 点击确认后，二者会随当前问问请求发送给已配置的 AI 服务；卡片在按钮附近明确提示这一点。
- 普通问问和点击 `不用` 不附带 Skill 内容。
- Skill 文件缺失、内容超限、版本过期或路径不安全时，停止本轮 Skill 调用，不静默换用其他文件。

## UI 状态

问问面板增加一个内联推荐卡片状态：

1. `匹配中`：本地读取目录，输入框暂不重复发送；
2. `待确认`：显示候选和三个动作；
3. `执行中`：卡片显示“正在使用 X Skill”，沿用现有回答进度/停止控制；
4. `已使用`：回答顶部显示 Skill 名称和版本指纹；
5. `匹配失败/Skill 过期/服务不可用`：显示原因和可执行的重试或普通问问路径。

若用户在待确认期间修改问题，旧推荐作废，重新匹配；不会把旧 Skill 误套到新问题上。关闭面板或切换对话不会自动发送待确认任务。

## 错误处理

| 情况 | 用户看到的结果 | 是否发送外部模型 |
| --- | --- | --- |
| 没有匹配 Skill | 直接走普通问问 | 是，按普通问问规则 |
| 本地匹配暂时失败 | 重试匹配 / 继续普通问问 | 只有用户选普通问问时才发送 |
| 用户点击“不用” | 普通问问回答 | 是，不带 Skill |
| Skill 版本已变化 | 要求重新匹配 | 否 |
| Skill 内容无效或超限 | 显示 Skill 不可用，可改走普通问问 | 否，除非用户明确选择普通问问 |
| AI 未连接或密钥缺失 | 沿用现有问问连接提示 | 否 |
| AI 请求失败 | 保留原问题和已产生的回答，允许重试 | 由现有问问重试语义决定 |

## 安全约束

- Skill 内容视为不可信资料，使用分隔标记注入，不能覆盖系统规则或工具权限。
- 复用现有 Skill catalog 的 canonical path、符号链接拒绝、单文件大小和正文上限。
- `skillId`、版本指纹和推荐结果使用严格 schema；拒绝未知字段、任意路径和旧版本重放。
- 本轮不执行 `scripts/`，不读取 `.env*`、密钥或隐藏目录，不增加新的写文件工具。

## 验收与测试

1. matcher 单元测试：名称/描述/触发词命中、无匹配、最多 3 个候选、稳定排序和特殊字符边界。
2. Skill API 集成测试：匹配请求 schema、无绝对路径输出、目录不存在/版本变化/正文超限的错误。
3. Assistant service 集成测试：未确认时不创建外部模型调用；确认后注入正确 Skill；旧版本被拒绝；普通问问不带 Skill。
4. `AssistantPanel` 组件测试：匹配卡片、使用/不用/换一个、修改问题使推荐失效、错误和重试状态。
5. Electron 端到端测试（开发版与打包版）：在临时大脑中放置两个 Skill，输入任务，确认一个 Skill，验证模型收到该 Skill 的方法说明、对话显示已使用 Skill，且本地资料和 Skill 文件字节未被改写。

## 不在本轮范围

- 多个 Skill 自动串联；
- 让 AI 自己决定是否执行而绕过用户确认；
- 自动把回答保存为文章、知识或大讲堂文件；
- Skill 编辑器、版本管理、删除和脚本执行；
- 用外部模型预先做 Skill 分类；
- 音频、视频、公众号发布等后续内容生产步骤。
