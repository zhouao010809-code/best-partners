# 提炼工作台 UI 改版建议

状态：用户已确认双栏工作台方案，进入实现。历史界面证据保留作为改版依据。

## 结论

推荐从“查询表格 + 独立历史 + 多页跳转”调整为“状态导航 + 资料列表 + 右侧工作区”。保留现有暗色、绿色重点色与固定左导航；首页牌堆不在此次改版范围。

用户要完成的任务是找到一份资料、看懂它、开始提炼、找回结果，而不是管理文件路径和接口状态。

## 方案比较

1. **双栏工作台（推荐）**：左侧选择资料，右侧原文、提炼准备和结果；处理多份资料时保持位置与筛选。
2. 单列表精简：字体、筛选与按钮可快速改善，但仍要往返多个页面，不解决连续处理问题。
3. 多列看板：状态直观，但长标题、原文和候选需要阅读空间；本阶段无需拖拽流转，不优先采用。

## 推荐布局

```text
固定导航 │ 提炼工作台
         │ 待提炼 · 提炼中 · 已有结果 · 未完成
         │ 搜索资料                     来源 / 更多筛选
         ├──────────────────┬─────────────────────────
         │ 资料列表          │ 选中资料标题
         │ 标题（最多两行）  │ 来源 · 采集日期
         │ 来源 · 日期 · 状态│ 原文 / 提炼结果
         │                  │
         │ 最近采集优先      │ 阅读或处理当前资料
         │ 保留选中项        │
         ├──────────────────┴─────────────────────────
         │ 当前状态                     一个明确的主操作
```

- 默认待提炼只放已归档、当前可开始的资料；部分入库资料继续在原始资料中查看，不混入默认任务列表。记录加载失败时不把“未知”伪装成未提炼。
- UI 工作进度与原始 Markdown 入库状态分开：已有候选仍可保持 YAML 未提炼，但在工作台标记已有结果。不更改 YAML 枚举或原文件。
- 输入搜索后自动更新；来源用已有平台选择器；日期筛选收进“更多筛选”，有条件时显示可清除标记。
- 列表标题采用正常可读字号与两行换行，路径折叠到资料详情；最新采集优先，无日期的资料排后。
- 点击资料在右侧预览原文；有结果直接打开结果，不再先绕到新提炼页。切换资料、返回队列保留搜索、状态及选中位置。
- 未开始：主操作“开始提炼”，进入紧凑的阅读状态选择及发送前核对。
- 进行中：显示“正在提炼”和“停止”；不显示虚构百分比。
- 已有结果：主操作“查看结果”；重新提炼作为次操作，历史版本在详情内查看。零候选显示“未发现可复用知识”，不标为待审阅候选。
- 未完成：直接给出原因与“重新准备”；如果此前有成功结果，仍保留该结果入口。
- 发送确认仍保留，完整发送内容可展开查看；不让原始提示词和规则占据默认阅读区。不增加审批层级。
- 桌面宽窗口双栏；窄窗口采用列表与详情单页切换并提供明确返回，应用导航始终留在左侧。

## 必要的数据配合

现有提炼记录接口最多返回最近 50 次（`src/server/services/extraction-service.ts:194`、`src/shared/api/extraction.ts:38`）。不能因为记录没出现在这 50 次中就推断资料从未提炼，也不能用它推算全量状态数量。

落地时应补一个只读的按资料汇总查询，返回最近运行、最近成功结果、进行中状态及来源版本是否一致；结果与历史支持分页。列表摘要不携带完整候选正文，选中后再读取详情。来源移走后的历史仍可找回；来源变更时提示结果来自旧版本，不能把路径相同当作内容相同。

## 范围与验收

只调整队列、提炼详情、相关导航文案和必要的只读状态查询。不做候选编辑、正式入库、批量提炼或自动调用模型。

验收以操作为准：首屏看见可处理资料；一眼区分新资料与已有结果；在同一工作区完成选择和查看；旧结果不会诱导重复调用；窄窗口不重叠。只为状态映射、旧结果识别和异步切换等实质行为验证，不为纯字号、间距与文案调整新增重复测试。
