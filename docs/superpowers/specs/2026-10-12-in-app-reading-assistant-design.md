# App 内选段学习助手 · 第一版设计

日期：2026-10-12。实现基线：`desktop-read`，`ea28c9e`。

状态：用户已批准实施。选段快照、只读学习会话和本机学习笔记已接入；实施与验收记录见[实施计划](../plans/2026-10-12-in-app-reading-assistant.md)及[验收文档](../../reviews/2026-10-12-reading-assistant.md)。真实模型理解效果仍待试用。

## 1. 目标与完成标准

用户正在 App 里阅读收藏的文章，遇到不理解的句子，希望直接提问、连续追问，并留下自己整理后的理解。

第一版闭环：`阅读 → 选中文字 → 问问这段 → 核对引用并发送 → 解释与追问 → 保存理解 → 再次打开资料时找回`。

成功的最低标准：用户完成一次真实阅读任务，不需要复制到其他聊天工具；能说出原文意思，并在重启后找到自己保存的理解及对应出处。自动化验证证明流程和数据行为，不能代替对解释质量与理解效果的真人验证。

## 2. 当前事实与缺口

以下为设计时基线的源码检查结果，保留用于说明改动动机；当前实现与运行证据见验收文档。

| 能力 | 已确认的实现 | 本次缺口 |
| --- | --- | --- |
| 原文选段提问 | `AppShell.tsx` 在 `/library`、`/knowledge`、`/queue` 的限定正文区采集选文，打开问问并预填问题和资料路径 | 选文只拼在问题字符串中；超过 6000 字静默截断；没有独立的来源版本快照 |
| 会话与草稿 | `AssistantPanel.tsx`、`useAssistantDrafts.ts` 支持固定资料、追问、历史和输入草稿恢复 | 固定当前检索范围不等于清除旧对话，需要保证学习会话不混入其他资料或项目历史 |
| 引用 | `AssistantMessageView.tsx` 支持证据片段、行号/页码、版本及打开全文 | 用户选文和模型实际读取证据要分别记录，不能用用户选文冒充后端核对过的证据 |
| 工具 | `tool-factory.ts`、`brain-tools.ts` 已有按范围读取和禁用候选写入的组合点 | 学习路径需要明确的只读工具集合，不能只靠提示词禁止动作 |
| 保存 | `assistant-drafts.ts` 保存待发送文字；现有提炼工具保存结构化候选供审阅 | 输入草稿与提炼候选都不等于用户整理的学习笔记；回答目前只有复制与追问入口 |
| 外部助手 | `mcp-server/` 已有独立只读 STDIO MCP | 不需要为本轮新增端口；当前 MCP 不读取计划中的学习笔记 |

## 3. 方案取舍

| 方案 | 投入与限制 | 选择 |
| --- | --- | --- |
| 在现有问问中增加明确的学习路径 | 复用阅读器、模型连接、回答渲染和历史；补引用快照、会话边界及轻量保存 | 推荐，第一版采用 |
| 只改提示词和快捷文案 | 改动少，但选段与来源仍混在文字里，也无法专门保存理解 | 不足以完成闭环 |
| 独立重建学习中心或先接外部 Agent | 会增加页面、配置和上下文交接，延迟验证阅读价值 | 后续按实际需求评估 |

## 4. 用户流程

1. 用户在现有 Markdown 阅读区选择文字，出现现有的“问问这段内容”。保留 `/library` 原文、`/knowledge` 正文、`/queue` 原文三个既有入口，主验收从收藏文章的 `/library` 开始。未提交候选、元信息及项目文件不归入本次选区入口。
2. 点击后打开现有问问侧栏，上方展示“你选中的文字”卡片，含资料标题、选文、回看原文入口。输入框预填“请用容易理解的话解释这段内容”，用户可修改。
3. 发送区说明“选中文字与当前资料可用于解释”，可展开查看选文及读取范围。点击发送才调用模型；不额外弹出一个重复确认框。学习路径沿用已配置模型，不要求用户先配置外部 Agent。
4. 回答先解释这段话，再按需补上下文或例子；没有必要时不套长模板。资料原意、模型补充和举例要能区分；回答中的来源引用复用现有证据预览。初版只放“说简单点”“举个例子”两个追问快捷入口，同时保留自由提问。
5. 当前学习会话固定同一份资料。新进入学习路径，或换到另一份资料发起选段提问时，创建新学习会话；同一资料内选新段可继续。切换页面本身不替换已固定引用。原问问中已有草稿或正在运行的回答时，复用现有排队/草稿保护，不覆盖也不自动发送。
6. 回答下提供“保存理解”，打开可编辑内容区，预填这条回答，允许用户改成自己的表述。原句与出处单独保留。明确点击保存后，才显示“已保存学习笔记”。返回阅读器后可在当前资料下展开“学习笔记”找回，不新增主导航。

## 5. 选段与上下文契约

- 增加明确的学习用途标记及可选选段对象，在 intent、待发送草稿、发送协议、消息历史中连续传递。旧消息缺字段时按旧行为显示，不推测其曾经的选区。
- 选段对象保存：资料相对路径、标题快照、阅读器展示时的 `rawSha256`、选中文字。用户问题与选文字段分开保存；资料身份和版本来自实际已加载正文，不只从页面 URL 猜测。
- 选文上限为 6000 个 Unicode 码点，首尾去空白；超限明确提示缩小选择，不静默截断。正文加载失败或尚在核对版本时，不创建新的选段快照。
- 发送前服务端核对路径可读及版本；原文已更新、回收或不存在时，保留问题和选文，显示重新打开/重新选择的下一步，不悄悄以新原文解释旧选段。后续读取仍需核对同一版本，出现变化终止本轮读取。
- 学习会话默认允许读取当前一份文档，不能显示为“只发送选中一句”。模型按需读取的实际片段使用已有引用机制记录；“有权限读当前资料”和“已经读取全文”分别表达。
- 选文是用户选择内容的快照，不能直接伪装成已核实的精确行号。初版回源打开整份资料并保留引用卡，不承诺逐字高亮；DOM 与原始 Markdown 偏移映射、PDF 画布选区和 OCR 不纳入本次。
- 学习用途在服务端限制工具为当前资料的只读能力；不提供归档、候选提交或项目写入工具，也不加载 Skill 推荐。学习会话的后续消息沿用服务端保存的用途和资料绑定，不能只靠首条消息的前端标记约束。
- 本轮继续复用现有模型适配器。学习用途只描述当前能力，不把旧项目会话改成学习会话。用户明确想转入通用问问时另开会话，并保留学习记录。

## 6. 保存理解的含义

第一版把它保存为本机 App 数据库中的“学习笔记”，与当前大脑绑定，与原资料关联。它不是未发送消息，也不是正式知识入库。

最小记录：笔记 ID、大脑身份、资料路径与标题、原文版本、选文快照、关联会话与回答 ID、用户确认的标题与正文、创建与更新时间、修改版本。前端不可跨大脑读取或保存；复用当前运行实例的大脑身份作为服务端边界。

- 笔记不依赖原会话仍存在：它自己保留正文、选文和出处快照。
- 保存不调用模型。重复点击或响应丢失后重试不产生重复笔记；编辑冲突保留用户输入，不能覆盖另一个窗口的修改。
- 用户可从原资料下重新打开、编辑并保存笔记。首版不增加批量管理、标签系统或全局笔记工作台。
- 原文移入回收站或丢失时，已保存笔记仍可从对应学习会话打开，显示来源状态。笔记不因原文回收而被删除；源文恢复后可重新回看。跨大脑切换不混入其他大脑的笔记。
- 不把 AI 回答默认写入 `02知识库`，不改原文、YAML 或既有知识状态。将学习笔记转成正式知识的审阅/入库属于后续独立流程。
- 首版笔记不进入个人 MCP 搜索，界面不承诺外部 Agent 已能使用它；对外复用仍使用现有已入库知识。笔记 Markdown 导出与正式知识转化列为后续需求，不占用本轮验证闭环。
- 学习笔记属于 App 本机数据；备份边界随应用数据库，不能声称复制大脑 Markdown 文件夹就包含这些笔记。

## 7. 实现边界

复用现有服务，按职责补最小模块：

| 部分 | 职责与依赖 |
| --- | --- |
| 阅读区选段采集 | 接收当前已加载资料身份、版本、正文区域，输出快照；从 `AppShell` 中抽出这一局部逻辑，不扩大全壳重构 |
| 学习引用卡与输入 | 展示/移除待发送选段、保护旧草稿、启动或继续正确会话；复用 `AssistantPanel` |
| 学习请求边界 | 服务端固定用途、来源和版本，只提供读工具；沿用现有模型、停止、超时、重试和实际证据记录 |
| 学习笔记服务与编辑区 | 新增独立记录和小型保存/读取接口，复用数据库迁移与冲突处理模式；不复用语义不同的输入草稿表 |

本次暂停通用 Agent 新扩展；不删除已有项目功能，不修改外部 MCP 契约，不改浏览器插件。源码变更与验证在实施计划中记录。

## 8. 验证与证据边界

使用隔离大脑、隔离 `userData` 和合成资料；模型用固定响应替身，不使用真实用户资料或密钥做自动化验证。延续[首次使用走查](../../reviews/2026-09-11-first-run-walkthrough.md)和[分发验收](../../reviews/2026-09-14-distribution-acceptance.md)的证据等级，当前首页契约以 `tests/electron/first-run-walkthrough.test.ts` 为准。

必要验收：

1. 三个既有正文入口都能建立正确引用卡；跨区选择、空选区、超限、正文版本变化有明确处理。选中和打开面板不发模型请求。
2. 发送、同文追问、换文新会话、恢复历史和重启后仍指向正确来源；原有草稿不丢失，其他会话内容不被带入新的学习会话。
3. 学习请求不能调用写工具或读其他文档；实际读取证据和用户选文分开呈现；故障后能停止/重试且不重复发送。
4. 保存、编辑、失败重试、重复点击、冲突和重启恢复均保留正确笔记；回收原文不连带删除笔记，原文/正式知识文件保持原字节。
5. 跑受影响组件与服务测试，再用隔离 Electron 做一条完整阅读→提问→追问→保存→重启找回的流程；分发前按仓库既有发布验证执行打包验收，不用开发版结果代替安装包结果。

真实效果另行验证：在已授权真实模型调用的试用中，让用户选几篇平常会读的文章，观察是否无需复制即可问清、能否用自己的话解释、是否愿意保存，以及第二次能否找回。记录从点击发送到有效解释的耗时；追问多不自动等于效果好，也可能说明首答不清楚。本设计没有设定或宣称已达到量化提升。
