# 设置页减法重排设计

状态：已实现并验证。

## 目标

设置页需要同时满足两件事：用户能在几秒内找到真正需要修改的配置；故障排查信息仍然可追溯，但不抢走配置主线。当前页面把“设置、运行诊断、资料问题、版本信息”连续铺开，造成纵向过长、重复状态多、主要操作不突出。

本轮采用“紧凑仪表盘 + 保留原有能力”的方向：不新增设置能力，不改变数据或桥接契约，只调整信息分组、视觉层级和入口位置。

## 用户可见结构

### 1. 页面头部

- 标题保持“设置”，副标题收敛为“管理大脑位置、AI 连接和应用版本”。
- 右上角只保留一个紧凑连接状态与当前 App 版本摘要。
- 版本号不再在页脚重复出现；更新卡仍展示完整当前版本。

### 2. 需要用户操作的三张主卡

桌面宽度下使用两列卡片，更新卡横跨整行；窄屏自动变为单列。三张卡是设置页唯一的主操作区域：

- **大脑文件夹**：保留真实显示名、当前绝对路径、连接状态、“在 Finder 中打开”和“更换大脑文件夹”。保留位置读取失败、选择忙碌、取消和重启提示。
- **AI 模型**：保留服务商、模型、密钥输入、保存/移除、连接验证及安全说明。把“读取异常 / 待验证 / 验证中 / 成功 / 失败”收敛为卡片右上角状态，避免同一状态在标题、正文和诊断区重复出现。
- **应用更新**：保留当前版本、最近检查结果、检查按钮、可用版本说明和官方 Release/DMG 操作。仍由用户手动触发，不自动下载、不静默替换应用。

主卡统一使用：标题 + 一句用途说明 + 状态 + 一组明确动作。减少空洞边框和过长的段落说明；安全、费用和重启等必要提醒保留为次级文字。

### 3. 次级提醒与诊断

- 当资料检查存在问题时，在主卡上方显示一条紧凑提醒，只展示数量、影响说明和“查看待确认资料”入口；不在设置首页直接展开文件列表。
- 运行状态压缩为一条状态摘要（本地连接、索引版本、结构问题数量）和“操作与恢复”入口。
- “待确认资料”和“高级诊断”继续保留为默认收起的 disclosure；展开后仍使用现有纯文本原文查看、Finder 定位和诊断内容。
- 详细诊断不再与三张主卡争夺同等视觉权重，但不能删除其可访问入口。

## 删除或合并的内容

- 删除页脚单独的 App 版本显示，合并到头部摘要和更新卡。
- 删除或改写重复的“本地状态快照 / 已连接 / 索引状态”文案，只保留一个摘要来源。
- 删除设置主区中不产生操作的长段落；保留安全、费用、重启、资料不自动修改等必要边界说明。
- 不删除任何现有 API、IPC、状态机、错误重试或恢复入口；“删除”仅指视觉重复和主页面层级。

## 视觉方向

- 延续当前深色石墨底和低饱和绿色状态色，不引入新的颜色系统或强渐变。
- 卡片采用轻微层次和细分隔线；成功/连接状态使用绿色点，警示使用琥珀色，错误使用现有红色。
- 桌面宽度优先保证卡片内容可扫读；窄屏按“标题 → 状态 → 主要按钮 → 辅助说明”堆叠，按钮不被压缩到不可点击。
- 保留现有焦点轮廓、键盘顺序、`role=status/alert` 和 live-region 语义。

## 行为与兼容性

- 保持 `SettingsPage` 当前所有交互契约：Finder 打开、目录选择、DeepSeek 密钥安全存储与验证、更新检查/下载桥接、资料问题展开和高级诊断展开。
- 浏览器预览继续显示桌面能力提示，不渲染不能使用的桌面操作。
- 不自动检查更新，不改变 GitHub Release 白名单，不增加网络请求。
- 不改写大脑文件夹中的原始 Markdown、索引数据或用户密钥。

## 验收标准

- 首屏能同时看见三张主卡的标题和主要状态；无需先展开诊断才能找到 Finder、密钥或更新按钮。
- 桌面宽度下无大块空白，卡片之间的间距和按钮对齐一致；窄屏无横向溢出。
- 资料问题数量仍可见，点击入口可到现有详情；高级诊断默认收起且可恢复。
- 既有 Settings 组件测试、更新测试、类型检查和 Electron 入口回归继续通过；补充主卡结构、移动端堆叠和重复状态不再出现的断言。

## 非目标

- 本轮不实现自动更新、静默安装、版本发布流程或签名/公证。
- 不重做整个 App 的侧边栏、首页或 Skill 库页面。
- 不改变已有设置的业务语义和存储边界。
