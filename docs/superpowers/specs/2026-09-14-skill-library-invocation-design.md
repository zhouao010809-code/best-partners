# Skill 库与问问调用入口：最小可用版设计

**日期：** 2026-09-14  
**状态：** 用户已确认第一阶段只搭建 Skill 库；AI 调用链路留作后续阶段

## 目标

在最佳拍档侧边栏增加一个 Skill 库，稳定地发现、展示和阅读当前大脑中的本地 Skill，为后续“问问”按用户意图筛选 Skill 做好目录基础。

Skill 库是能力入口，不是单纯的文件浏览器，也不是任意电脑操作器。

## 第一阶段用户流程

```text
用户打开 Skill 库
  → 看到当前大脑 .claude/skills 下的 Skill
  → 选择一个 Skill 查看名称、描述和方法正文
  → 继续在本地文件中维护 Skill，刷新后看到最新内容
```

第一阶段不调用模型、不执行 Skill、不改变资料或知识文件。

## 数据源与真源

- 唯一数据源是当前大脑目录下的 `.claude/skills/<skill-name>/SKILL.md`。
- 用户继续在本地文件中创建和维护自制 Skill；App 不提供编辑器，也不复制一份可分叉的 Skill 内容。
- 每个包含 `SKILL.md` 的合法子目录作为一个 Skill。目录名映射为稳定 `skillId`，名称和描述来自 frontmatter；缺少描述时使用安全的默认文案。
- Skill 详情可以显示受控的 Markdown 正文和允许读取的参考文件清单，但不把脚本、`.env`、密钥或任意隐藏路径暴露给模型。

## 侧边栏与 Skill 库

- 新增 `/skills` 侧栏入口和页面。
- 页面列出真实发现的 Skill，显示名称、简述、版本指纹和“查看方法”入口。
- 本阶段不放置执行或“用于问问”按钮；后续接入问问时，再由检索链路根据 `skillId` 推荐并让用户确认。
- 目录不存在、为空或某个 Skill 无效时，显示可理解的空态/错误，不把空列表伪装成已加载成功。

## 为后续问问集成保留的契约

- 目录返回稳定的 `skillId`、名称、描述和版本/内容指纹；后续 AI 只提交 `skillId`，不提交文件路径。
- 后续问问可先依据目录元数据筛选并推荐 Skill，再由用户确认；确认后才按 `skillId` 读取有界的 `SKILL.md`。
- Skill 上下文不扩大知识检索范围、不授予文件写入、命令执行、网络访问或发布权限；现有知识工具和系统规则优先。

## 安全边界

- Skill 根目录由桌面端固定为当前大脑的 `.claude/skills`，renderer 和模型都不能提交任意绝对路径。
- 服务器使用独立的只读 Skill catalog reader 访问这个固定根，不放宽现有知识资料路径校验，也不把 `.claude` 加入通用文件读取 API。
- 读取时做 canonical path、符号链接和目录身份校验；只读 `SKILL.md` 及明确允许的 Markdown 参考文件，并限制单文件/总字符数。
- `SKILL.md` 内容视为不可信资料，使用分隔标记注入上下文；其中的文字不能改变系统权限或触发动作。
- 首版不执行 Skill 目录中的 `scripts/`，不读取 `.env*` 和凭据文件。

## 不在第一阶段范围

- App 内新建/编辑 Skill。
- 问问的 AI 推荐、确认和执行链路。
- 自动串联多个 Skill。
- 将草稿自动写入 `03大讲堂`。
- 排版、音频、视频导出或外部平台发布。
- 任意 shell/Node 脚本执行器。

## 第一阶段验收条件

1. 在真实项目 `.claude/skills` 放入或修改一个 Skill，刷新后能在 `/skills` 看到最新名称与描述。
2. 点击 Skill 后能查看受控的 `SKILL.md` 正文；正文中的 HTML、外部图片和危险链接不会被执行。
3. 每个 Skill 返回稳定 `skillId`，前端不暴露任意绝对路径给后续调用方。
4. `../`、绝对路径、符号链接、`.env`、脚本和未知 Skill 均不能被读取。
5. Skill 根不存在或读取失败时，页面显示具体错误，不把失败当作空成功。
