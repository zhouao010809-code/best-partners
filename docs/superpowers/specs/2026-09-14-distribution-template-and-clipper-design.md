# 最佳拍档完整分发体验设计

**日期：** 2026-09-14  
**状态：** 设计稿，待用户复核  
**目标：** 让新用户下载最佳拍档后，直接获得一套可用的本地知识库体系，并能完成浏览器收藏到本地收件箱的闭环。

## 1. 问题与边界

当前桌面 App 已经包含本地目录校验、资料归档、AI 提炼、候选审阅、知识入库和来源追溯逻辑，但首次创建的大脑只包含空目录和五份占位规则；浏览器插件也没有随 App 分发。新用户因此拿到的是“可以运行的引擎”，不是“下载后即可开始积累资料的产品”。

本设计解决两个缺口：

1. 将可公开分发的最佳拍档知识库模板内置到桌面包，并在首次启动时安全复制。
2. 将浏览器收藏插件和本机桥接能力作为桌面包的一部分提供，在首次启动中给出明确安装入口。

本设计不包含：

- 打包或公开用户当前真实大脑中的笔记、规则、账号、密钥和统计数据。
- 静默修改浏览器设置或绕过浏览器扩展安装确认。
- 自动将收藏资料发送给 DeepSeek；收藏进入本地收件箱后仍须用户预览、确认和单独授权 AI 发送。
- 同时支持 Windows、Linux、Safari；本阶段继续以 Apple Silicon macOS、Chrome/Edge Manifest V3 为交付目标。

## 2. 目标用户流程

新用户从干净安装开始，看到的是以下连续路径：

```text
下载最佳拍档
  → 首次启动
  → 创建“最佳拍档入门大脑”
  → 看到完整目录、规则和示例
  → 点击“安装浏览器收藏插件”
  → 在浏览器中确认一次安装
  → 点击“测试收藏”或保存一篇网页
  → 收件箱出现资料
  → 预览并确认归档
  → 配置 DeepSeek（可稍后）
  → 预览、确认提炼
  → 审阅候选并确认入库
  → 从知识回看原文
```

其中，创建模板是首次启动必经步骤；插件安装是希望使用浏览器收藏时的必经步骤，但不阻挡用户先用文件选择或粘贴文本。API Key、AI 提炼和正式入库仍由用户逐步确认，不在安装时强制要求。

## 3. 公开知识库模板

### 3.1 模板内容

新增公开模板目录 `templates/default-vault/`，只放可公开、无个人信息的内容：

```text
templates/default-vault/
├── 00大脑规则/
│   ├── 00_大脑规范.md
│   ├── 01_总路由规则.md
│   ├── 02_图书馆入馆规则.md
│   ├── 03_知识库提炼与入库规则.md
│   └── 05_链接命名与治理规则.md
├── 01图书馆/
│   ├── 小兆clipper/.gitkeep
│   └── 来自示例/2026-09/示例资料/
│       └── 示例资料.md
├── 02知识库/
│   └── 示例主题/
│       └── 示例知识.md
├── 03大讲堂/
│   └── .gitkeep
└── 最佳拍档入门说明.md
```

规则文件要用普通语言说明真实流程：原文保留、预览后归档、确认后发送、候选不等于正式知识、确认后入库、知识可回看来源。示例资料与示例知识必须是虚构内容，并在文件中明确标注“示例”。

### 3.2 首次创建行为

`createInitialVault` 改为复制模板目录，而不是在代码中写入五段占位字符串：

- 复制前校验目标父目录是实际目录，拒绝符号链接。
- 目标目录名固定为“我的大脑”；同名目录存在时不覆盖，提示用户换位置。
- 复制过程先写入临时目录，全部文件校验通过后再原子改名；失败时删除本次创建的临时目录。
- 模板内文件使用私有权限；创建结果再次经过现有 `validateDesktopVault` 校验。
- 已有大脑只做校验和加载，不自动升级、不覆盖用户文件。
- 在模板根目录写入 `template-manifest.json`，记录模板版本和公开内容指纹，供后续升级提示使用；不把个人资料写入清单。

### 3.3 模板升级边界

首次创建使用当前 App 内置版本。后续版本只提示“有新的公开模板可查看”，不自动替换用户已编辑的规则或示例文件；用户明确选择后，另建升级预览并逐项确认。模板升级不是首次闭环的阻塞条件。

## 4. 浏览器收藏插件与本机桥接

### 4.1 分发形态

新增 `browser-extension/`，采用 Manifest V3，包含：

- `manifest.json`：固定扩展标识、最小权限、内容脚本和 service worker。
- `src/content-script`：读取当前网页标题、原始链接、可读正文和发布时间候选。
- `src/service-worker`：处理“保存到最佳拍档”、去重、失败重试和状态提示。
- `src/options`：选择目标大脑、测试连接、查看最近一次发送结果。
- `README.md`：Chrome/Edge 安装步骤、权限解释和卸载方式。

桌面包内同时带有编译后的扩展目录和压缩包，首次启动可打开安装页。浏览器商店版本可在后续发布时替换安装页地址；在商店版本可用前，开发者预览版明确显示“从本地扩展目录安装”的步骤，不伪装成一键静默安装。

### 4.2 本机桥接方式

浏览器扩展不直接写用户磁盘，也不接受任意绝对路径。采用 Chrome/Edge Native Messaging：

1. App 首次启动时，在用户确认后安装本机 host manifest 和桥接可执行文件到用户级目录。
2. 扩展通过固定扩展 ID 连接 `local.bestpartners.clipper`。
3. Native host 只读取 App 写入的受保护桥接配置：当前大脑目录、随机配对令牌、允许写入的固定子目录。
4. host 校验消息大小、扩展 ID、令牌、路径和资料包结构后，以原子方式写入 `01图书馆/小兆clipper/<packet-id>/`。
5. App 收件箱按既有 5 秒轮询发现资料，继续使用现有预览、确认归档和恢复事务。

桥接配置放在 App 的 `userData` 私有目录，不写入公开大脑；令牌轮换时旧令牌立即失效。host 只能写入当前大脑的收件箱暂存目录，不能写入知识库、规则目录、任意用户路径或执行删除。

### 4.3 插件安装向导

首次启动创建模板后，在总览页显示一个条件式卡片：

- 标题：“安装浏览器收藏插件”
- 说明：“把网页收藏直接送进你的收件箱；浏览器会要求你确认一次。”
- 操作：“打开安装说明”“我已安装，测试连接”
- 备用入口：“先用文件或粘贴文本”

“测试连接”发送一份合成测试资料，成功后自动在收件箱显示“插件连接正常”；失败时显示普通语言原因和下一步，不删除模板、不清空已有资料。测试资料使用固定虚构内容，用户可在收件箱按普通资料流程移除或归档。

## 5. 数据与失败处理

### 模板创建

- 目标位置已有“我的大脑”：说明不会覆盖，提供重新选择。
- 无写入权限或磁盘空间不足：说明创建未完成，临时目录被清理，原有目录不变。
- 模板文件缺失或指纹不一致：阻止启动并提示重新安装 App，不生成半套大脑。

### 插件安装与连接

- 浏览器未安装：提供 Chrome/Edge 安装说明和文件导入备用入口。
- 用户取消扩展确认：保留当前大脑和页面任务，允许稍后再次打开安装说明。
- Native host 未注册：显示“插件已安装，但还没有连上最佳拍档”，提供重新安装桥接和测试连接。
- 连接中断或网络页面读取失败：扩展保留网页标题和链接，允许重试；App 不创建重复资料包。
- 资料包重复：按内容哈希复用已有记录，收件箱提示已有资料，不覆盖原文。
- App 未运行：扩展显示“最佳拍档未打开”，不丢弃本次网页信息；用户重新打开 App 后可从扩展重试。

### AI 与隐私

插件送入 App 只代表本地接收，不代表发送到模型。AI 发送仍沿用现有完整预览和确认；没有 API Key 时，用户可继续浏览和归档，不会在首次启动被强制拦截。

## 6. 文件与模块边界

### 新增

- `templates/default-vault/**`：公开模板和虚构示例。
- `browser-extension/**`：Manifest V3 扩展源代码、构建产物和安装说明。
- `src/electron/clipper-installer.ts`：安装/校验/卸载用户级 Native host，不改用户资料。
- `src/server/clipper/**`：桥接消息 schema、令牌校验、资料包生成与去重。
- `tests/electron/first-run-distribution.test.ts`：从空环境创建模板和插件安装入口。
- `tests/e2e/clipper-extension.spec.ts`：隔离浏览器配置下的收藏到收件箱流程。

### 修改

- `src/electron/settings-store.ts`：由模板复制替代占位规则写入。
- `src/electron/main.ts`：注册安装向导、桥接状态和安全 IPC。
- `src/client/pages/DashboardPage.tsx` 或对应首次使用组件：显示安装插件卡片和测试连接结果。
- `src/client/pages/intake/IntakeMailbox.tsx`：在无插件资料时继续说明文件/粘贴备用入口，在连接成功时显示来源状态。
- `scripts/package-desktop.ts`：将模板和扩展构建产物纳入桌面包，排除测试夹具和源码密钥。
- `README.md`：更新下载后完整流程、插件安装步骤和浏览器权限说明。

## 7. 验收标准

### 必须通过

1. 干净 `userData` 和空父目录启动，用户创建后得到完整目录、完整公开规则、示例资料、示例知识和入门说明。
2. 已存在的大脑启动不被覆盖，原始文件字节和配置保持不变。
3. 打包 `.app` 中能找到模板清单、扩展压缩包和 Native host 资源；不包含真实大脑路径、密钥或 `.local` 测试资料。
4. 隔离 Chrome/Edge 配置中安装扩展并完成一次合成收藏，App 收件箱在 5 秒内出现资料。
5. 收藏失败、App 未运行、用户取消安装、重复收藏和桥接令牌失效都有普通语言提示，且不丢当前网页信息或已有任务。
6. 从插件资料进入现有预览、确认归档、配置模型、提炼、候选审阅、确认入库和来源回看流程，原文和附件保持不变。
7. 真实账号、真实大脑、真实 API Key、真实对外授权和真实付费调用不参与自动化验收。

### 明确未承诺

- 浏览器商店审核通过时间和商店上架状态。
- 未签名/未公证 DMG 在其他用户 Mac 上的 Gatekeeper 体验；正式公开发布仍需 Developer ID 签名和 Apple 公证。
- OCR、图片问答、DOCX 解析等当前已有文档标记为未支持的能力。

## 8. 复查规则

后续新增功能时，必须重新检查：

1. 新用户是否仍能从下载进入完整模板，而不是落回空白占位规则。
2. 插件是否仍能在没有真实大脑路径和账号信息暴露的情况下完成本地收藏。
3. 每个外发、写入、删除或权限变化动作是否仍有独立预览、确认和可恢复记录。
4. 插件不可用时，文件选择/粘贴入口是否仍能让用户继续完成核心任务。
