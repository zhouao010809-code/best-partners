# 设置功能闭环实施计划

**Goal:** 用户能确认当前大脑、独立验证 AI 配置，并在操作失败后继续完成设置。

**Architecture:** 保留单栏设置布局；使用现有 Electron IPC 和带 CSRF 的本地 API。连接验证使用服务端保存的密钥与固定短消息，结果绑定密钥版本；文件定位限制为当前大脑内的真实 Markdown 文件。

**Tech Stack:** React、TypeScript、Fastify、Electron、Vitest。

本计划落实用户已批准的产品评审项，继续当前 worktree，不提交或重置既有工作。

- [x] AI 后端：保留密钥读取故障原因；新增显式验证 API，认证、余额、限流、超时及网络错误提供可操作反馈；限制响应、时间、重定向与并发，验证不产生提炼记录。由独立 Agent 编写 provider/service/API 测试并验证。
- [x] 桌面：提供当前大脑真实路径和打开入口；无效目录重新选择；有效目录切换前明确重启影响；资料定位通过主进程校验。用可注入原生能力验证取消、重试、错误及路径边界。
- [x] AI 表单：保存失败保留并隐藏输入；成功后清空；区分未配置、读取异常、待验证、验证中、验证成功和验证失败；测试只由用户点击触发，编辑未保存密钥时禁止误测旧配置。
- [x] 设置结构：移除没有可调整项的收件归档分组；目录区呈现路径和操作；运行与资料诊断保留在次级区域；补 App 版本，增大中文说明与控件文字，保持窄屏和键盘操作。
- [x] 资料问题：提供字段处理建议和原文件定位，保持原文只读；说明保存后需等待扫描再刷新列表，不把列表刷新伪装成重建索引。
- [x] 验证：运行相关组件、后端及桌面单元测试和 typecheck；构建 client/server/electron；在隔离 fixture 检查桌面和窄屏、新增状态及操作；备份运行包后更新并验证真实设置页面。

验收不调用真实模型、不修改真实密钥、不切换真实大脑、不更改用户笔记。真实网络连通性由用户自行点击验证，测试覆盖使用受控响应。
