# 首次使用核心任务走查与最小修正计划

**目标：** 以第一次打开、没有配置、不了解内部术语的用户为起点，确认他能否把一份收藏资料走完“收到 → 归档 → 提炼 → 确认入库”的最短闭环；只修复阻断闭环的最小文案与入口问题，不把非必要设置变成首次必填。

**范围：** `desktop-read` 工作树的首页、收件箱、提炼入口与牌堆空态；隔离测试数据；不触碰正式大脑、真实账号、真实密钥、外部授权、对外发送或支付。

## 2. 先写失败验收（TDD）

在生产代码之前补充组件验收，覆盖：

- 空收件箱说明资料来源与下一步，且连接失败状态仍与空态区分；
- 首页用普通语言说明“把收藏资料变成可复用知识”，并解释“待提炼”；
- 有待提炼资料且模型未配置时首页出现一次点击可达的设置提示；已配置或无待提炼资料时不出现；
- 首页牌堆为空时提供前往收件箱的明确操作；
- 整理单在填写前明确未归档字段只保留在当前页面；
- 现有编辑字段保留、显式预览/确认、失败重试和配置用户路径的原有验收继续通过。

运行新增断言，确认在当前实现上先失败，再进入实现阶段。

## 3. 实施最小修正

- 在 `IntakeMailbox` / `IntakeTray` 空态补一条普通语言说明：收件箱会接收浏览器剪辑插件的收藏，同时提醒用户可用页面上方的文件选择/粘贴入口；不新增强制引导或必填字段。
- 在首页“继续工作”附近补一条功能说明和首次出现的术语消歧；保持现有布局、阶段计数和继续任务卡。
- 仅当首页已有待提炼队列且 health 明确为未配置模型时，显示“开始提炼前需要配置 DeepSeek 密钥”的轻量提示，并直达设置；不在无资料时强制配置。
- 在首页牌堆空态旁增加收件箱链接；不改 `MaterialDeck` 的通用调用契约，其他页面保持兼容。
- 在整理单步骤条下增加一条短边界提示，说明未归档内容只保留当前页面；不新增数据库草稿对象。
- 只增加必要的局部样式，保留现有视觉层级、键盘焦点和 reduced-motion 行为。
- AI 失败按类别提供可执行入口（密钥去设置、余额明确提示、其他可重试），失败重试保留阅读状态。
- AI 发送预览显示上下文大小与上限；候选阅读区显示原文逐字摘录数量；超限文案明确“尚未发送”和拆分/减少范围的下一步。
