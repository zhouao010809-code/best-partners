# 创作取舍与可恢复回收 · 2026-09-26

## 问题与修复范围

用户在 Skill 库新建分类后没有删除入口；项目选题生成后全部自动入库，不满意的建议无法永久放弃，采用新稿和载入旧版本也没有保留被替换的工作稿。

本次修复个人版已有流程的退出和恢复，不修改公司模式、项目源文件，也不增加永久删除。

## 当前行为

- Skill 自定义分类先预览整个文件夹范围，确认后整包移入 `.claude/skills/.trash`。隐藏文件和未识别内容一起保留；可以即时撤销，也可重新打开应用后从文件夹回收站恢复。未分类没有回收按钮。同名目标、目录身份变化或预览过期时拒绝移动；异常记录保留内容供核对。
- AI 选题先显示候选，只有勾选并点击保存后才进入选题库。未选建议可放弃。候选保存携带固定请求编号与档案版本，重复请求不会生成重复条目，档案变化会拒绝过期候选。
- 选题、脚本从列表或编辑器确认移入项目回收站，保留原 ID、正文、版本、定稿与讨论。可以撤销或恢复；已回收条目不计入 200 条有效创作容量。恢复容量不足时保留回收内容。
- 被回收条目同时退出创作档案的样稿引用。恢复后由用户重新选择样稿。已导出文件保持原样，不自动删除或重建。
- “放弃建议”保存在讨论记录中，重新进入不再弹回；仍可在讨论历史查阅。
- AI 替换和载入历史版本前，先保存当前稿的独立版本；失败则不替换。提供“撤销这次替换”，版本记录作为长期恢复入口。返回编辑器前保存失败会留在当前页面；回收不会清除另一窗口尚未保存的恢复稿。
- 档案候选可以放弃，参考资料未应用选择可以取消。

## 状态与并发

- 迁移 `024` 给创作增加 `discarded_at`、创建请求编号/摘要，给讨论增加 `dismissed_at`；旧内容默认有效。
- 丢弃和恢复采用 revision 校验。丢弃后拒绝保存、生成、记录迟到讨论、定稿与导出；丢弃再恢复也不会接收旧修订号的结果。
- 导出进行时拒绝回收；正在使用的样稿被回收后，旧档案生成结果不得落入讨论。
- Skill 回收采用持久操作记录、完整目录元数据复核、原子 rename 与重启核对。仅在当前大脑的个人 Skill 根目录内操作，不触及全局 Skill 或公司工作区。外部进程恰在检查和 rename 系统调用之间替换目录的防护仍受 Node 文件系统原语限制；未声称原生句柄级安全删除。

## 设计推断与未验证

- 入口就近放置、先取舍再保存、回收可恢复有助于减少界面累积和误操作成本；这是设计推断，尚未做真人可用性研究。
- 项目绑定移除、永久删除和取消定稿不在本轮范围；本轮处理分类目录与创作结果的取舍。
- 未签名开发者预览的分发边界沿用当前版本，尚无 Apple Developer 签名或公证。
