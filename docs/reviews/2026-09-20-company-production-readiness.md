# 公司版双 Mac 试运行审查 · 2026-09-20

## 结论

当前版本已经从“三个页面原型”进入可落地的两人试运行阶段。它已经支持通过视频号、抖音、小红书官方后台导出的 CSV/XLS/XLSX 文件自动入库并汇总到看板，但仍不是绕过平台授权的完整代运营 SaaS。可交付的核心是：

- 项目文件夹是真源，SQLite 只做投影、会话和审计记录；
- 项目档案、Skill 库和诚实显示数据缺口的项目看板可共享使用；
- 三个平台的导出文件按项目目录自动扫描，保留带 SHA-256 的原始证据，重复文件、行级拒绝和逻辑冲突可追溯；
- Codex / WorkBuddy 通过公司 MCP 读取项目和 Skill，并通过“扫描提案 → 人工核对 → 确认”落项目；
- Mac mini 有明确的启动密钥、登录限速、运行锁、优雅停机、冷备份和恢复校验路径；
- 推荐只绑定回环地址，第二台 Mac 通过 SSH 隧道访问，避免密码和 session 在办公室网络中明文传输。

## 已观察实现

### 运行时与权限

- company 运行时对个人 `/api/v1/*` 业务路由失败关闭，只保留用于前端选择路由树的 `/api/v1/bootstrap` 探针。
- 首次创建 operator / reviewer 必须提供 43 字符的 base64url 形状启动密钥；部署命令用 `randomBytes(32)` 生成 256-bit secret，缺失、错误或弱格式都在密码派生和数据写入前被拒绝。
- 新密码最少 12 字，两账号不能复用同一密码。存在和不存在的用户都做 scrypt，减少用户名时序枚举；同一来源和账号的并发失败尝试有 5 分钟窗口限制，进程内密码派生同时最多 4 个，超出立即返回 429 不排队。
- 数据库只存 session ID 的 SHA-256；浏览器仍在 HttpOnly/SameSite=Strict cookie 中携带随机 session ID。写接口另要求精确 Origin、有效公司会话和 CSRF token。

### Agent 与文件边界

- MCP 只暴露 11 个公司工具，宿主可从 annotations 区分只读、提案写入、最终确认和平台导入操作。
- 扫描写入默认关闭；最终确认还有第二个独立开关和由宿主设置的精确确认意图。只允许与已核对 `runId`、名称、状态、来源 hash 和 Skill ID 完全相同的一次调用。
- MCP 不跟随 HTTP 重定向，避免密码或确认请求被转发到其他 origin。HTTP API origin 只允许回环；返回的项目路径、证据路径和 Skill 参考文件要再通过相对路径检查。
- 项目 API 对外只返回工作区相对路径，并完整返回 `selectedSkillIds`；机器绝对路径不会进入项目列表、详情或 Agent 工具结果。

### 运维与恢复

- 公司服务要求显式绝对工作区和状态目录，不再默认写入代码仓库。
- 运行时使用独占锁阻止两个公司进程同时打开同一状态目录。`SIGINT` / `SIGTERM` 会关闭 Fastify、SQLite 和运行锁。
- 备份工具只允许冷备，会拒绝运行锁、符号链接、特殊文件、重叠路径和复制中的源变化；快照不覆盖，并保留文件级 SHA-256 清单。
- 恢复校验只读，会拒绝缺失、篡改、多出顶层文件或符号链接的快照。launchd 模板不把 bootstrap token 本文写入 plist。

## 设计推断与剩余边界

- 对于当前“老板 + 运营”两人试运行，文件真源 + Agent 提案 + 人工确认比继续扩张手填 CRUD 页面更合适。这是产品设计判断，不是用户研究结论。
- 公司服务仍允许在受信私网 IP 直连，但直连 HTTP 没有传输加密。本轮可交付路径是回环 + SSH 隧道；如果以后改成反向代理，必须同时重做 public origin、可信代理、Secure cookie 和 HSTS，不能只加一层 TLS 转发。
- MCP 客户当前没有统一的请求超时或 AbortSignal 传递；调用者取消后，已发出的后台请求可能仍会完成。确认意图会在发起 HTTP 请求前消耗，结果不明时必须先查同一 runId；这是后续 P1 改进项。
- 登录限速是进程内窗口，重启后清空；对两人、SSH 隧道的 P0 足够，不是多租户公网鉴权方案。
- reviewer 当前是只读核对角色，没有独立的“老板审批后 operator 才能确认”双人审批流。
- 视频号、抖音、小红书的后台数据不通过私有接口、模拟登录或私信抓取接入；运营人员把官方导出文件放进对应项目目录后，服务启动即扫描、之后默认每 30 秒轮询一次（可用 `COMPANY_METRICS_POLL_MS` 调整），看板汇总可验证的快照。没有导出文件时仍显示“未配置 / 待建立基线”，不伪造实时数字。

## 后续加功能时的复查规则

1. 新的平台数据接入必须先定义数据来源、授权、取数频率、失败显示和原始回执；不允许把未知数据写成 0。
2. 新的 Agent 写工具必须默认关闭，标注 MCP annotations，使用结构化输入，保留幂等回执，并不得返回机器绝对路径。
3. 新的 Skill 必须仍以文件为真源；网页展示和 Agent 阅读不能把 Skill 正文自动升格为可执行命令。
4. 任何数据库迁移、项目文件格式或目录调整，都必须先做冷备份、恢复校验和新路径启动演练。
5. 如果将服务暴露在 SSH / VPN 之外，必须把 TLS、public origin、Secure cookie、网络 ACL 和持久化登录限速当成同一个交付项复查。
