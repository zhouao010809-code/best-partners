## 范围与方法

以 `3d1d2c1` 为基线，包含当前工作树尚未同步的完整 Autoloop 接入。盘点一方实现 410 文件、约 6.1 万行，覆盖 `src`、`scripts`、`native`、浏览器扩展、个人和公司 MCP，另核查工程配置、锁文件、CI 及测试发现入口。生成产物、第三方依赖没有逐行审查。

先执行全目录基线测试，同时独立审查客户端、服务端及桌面构建。对确定缺陷补可重复触发的回归，修复后做第二轮交叉审查，再在冻结源码上执行构建和桌面验证。测试通过不等于证明不存在任何缺陷。

## 架构结论

当前模块化单体适合个人桌面与可选公司服务端。React 经公共 API 合同调用 Fastify，个人资料以文件为来源，SQLite 保存索引、对话与操作状态。Electron 负责系统选择、启动退出和原生能力，两套 MCP 分别保留个人只读边界和公司身份/操作边界。Autoloop 通过本机协议接入独立执行服务，不把后台执行混入浏览器进程。

本轮未发现必须整体重写或拆成微服务的证据。实际问题主要发生在异步上下文切换、异常恢复、输入边界，以及开发环境和打包环境的差异。架构边界检查、类型检查和构建来源校验继续作为门禁。

## 已修复的问题

### 界面与任务状态

- 自动任务操作失败遇到在途轮询时，总览停止自动刷新。
- 配置读取与保存竞态导致重新读取按钮永久不可用。
- 来源标识未先去空格，可能覆盖已存在的来源。
- 个人项目重连预览和公司项目指标、待上传文件在切项目后串用。
- 公司 Skill 的旧读取结果覆盖新详情。
- 知识库与档案库连续搜索时，上一轮地址同步覆盖尚未提交的新输入。现保留本页输入，同时维持前进/后退的地址同步。
- 问问 Skill 推荐未随范围、附件、页码、模型等变化失效。
- 问问迟到发送、创建对话和打开草稿的回包/清理影响新项目。
- 跨项目切换发生在自动保存前时丢失草稿。保存队列、确认版本和失败副本现按服务及项目隔离，离开时立即保存，失败时保留可恢复文字。

### 数据与异常恢复

- 公司导入的合法原文件 `source-manifest.json` 与内部清单冲突。新暂存格式隔离原文件，兼容旧暂存记录，无数据库迁移。
- 超大指标文件在限制检查前已完整读取并复制。现在先检查大小、有界读取并复核变化，超限不产生 raw 副本。
- 指标相同内容跨平台导入被误判为成功去重，现明确拒绝平台冲突。
- 粉丝汇总取历史最大值而掩盖掉粉，现按平台和账号取最新业务日期，无账号时保留数据缺口。
- 回收/彻底删除的引用提示漏掉合法相对链接、标题和锚点，现统一解析并保守提示歧义。
- 长原文可提炼却无法入库。现于模型调用前核对完整原文与引用预算，对已有候选提供明确容量错误，不截断原文或恢复证据。
- Autoloop 连接保存的慢校验期间，外部 CLI 修改会被旧快照覆盖。现对三份配置原文做提交前版本复核，变化返回 409，并保留外部新版本。
- Autoloop 异常退出遗留空锁导致永久忙碌。现原子发布完整 PID 锁，回收过期空锁和已退出进程锁，仍保留活跃进程的锁。
- 浏览器收藏只在发送失败后持久化。现先写待发送记录再调用 native host，进程中断后沿用同一 packetId 重试。
- 浏览器待发送数据已提交但计数写入失败时误报未入队。IndexedDB 提交结果现为准，派生计数同步不会推翻成功的保存/删除。

### 桌面、构建与依赖

- 正式 Electron 的 `process.defaultApp` 为 `undefined`，此前误判为开发模式，首次创建大脑找不到模板。
- 切换大脑在可取消的退出前保存配置，现等所有窗口允许关闭后提交，取消时保留原连接和设置。
- 开发剪藏 wrapper 缺少应用入口，安装说明路径也错误，现区分开发/打包并检查打开结果。
- 插件连接测试把 native host 拒绝误报为成功，现保留真实失败状态。
- 更新资产构建补上来源与实际资源验证，拒绝缺清单、同版本旧包及被改动资源。
- 更新已公布漏洞涉及的运行与开发依赖，保留精确版本及锁文件，重新验证桌面 ABI 与构建。
- 发布入口漏跑 24 项 API 界面/公司入驻/卡片测试。新增独立配置复用已构建 runtime，纳入发布验证；macOS CI 从完整单元构建检查提升为整个发布门禁，并增加个人 MCP 构建。
