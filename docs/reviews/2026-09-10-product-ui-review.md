# 小兆大脑产品与 UI 评审 · 2026-09-10

本轮只做产品与设计评审，未修改应用代码。依据是当前运行页面的实际浏览，以及对应源码和交互约定；不是用户研究结论，也没有做动画帧率或整站对比度测量。

## 核心判断

黑银材质、邮筒、抽屉、文件夹和书柜已经形成统一的产品识别。下一轮应优先改善日常重复使用的效率：让当前任务更明确、审阅内容获得足够空间、每一步完成后自然接上下一步。

实体外观适合表达收藏与归档；进入查找、阅读、编辑后，应提供更紧凑的工作状态。保留目前的首次呈现，并让用户可以快速继续工作。

## 第一轮：优先处理

### 1. 工作台按任务分配空间

观察：默认候选详情宽 350px，中等窗口为 290px；柜子占据剩余大块空间。已有“展开阅读”，但需额外点击，展开后仍有较长的重复标题、元信息和工具栏。原文与结果只能切换查看。

- 定位：`src/client/styles/queue-drawer-workspace.css:14`、`:68`；`src/client/pages/queue/QueueDetail.tsx:52`。
- 建议：浏览资料时展示柜子；进入候选审阅时默认展开宽工作区，柜子退为可折叠的资料导航。
- 宽屏提供原文与当前候选并排；窄屏提供“查看依据”临时面板，返回后保留光标与滚动位置。
- 验收：进入审阅即可看到第一条候选正文；无需先找展开按钮；核对原文后不丢编辑位置。

### 2. 候选审阅改为逐条处理，并固定批次操作

观察：当前 4 条候选全部展开为长表单；批次操作在全部候选之后，队列 CSS 将批次栏设置为 `position: static`。用户要逐段滚动查看取舍、缺项和最终按钮。

- 定位：`src/client/pages/queue/CandidateReview.tsx:261`；`src/client/pages/queue/ingestion/ReviewFields.tsx:30`；`src/client/styles/queue-drawer-workspace.css:65`。
- 建议：候选目录显示标题、选入/稍后/放弃、缺项数和保存状态；正文区域默认展开当前候选，允许展开其他候选比较。
- 默认先看排版好的内容，需要修改时进入编辑。补充字段按需展开，缺项提示可直接定位对应字段。
- 底部固定“已选 N 条 / 待补 M 项 / 预览入库”；草稿保存和正式入库的状态分别表达。
- 验收：任意滚动位置都能确认当前批次；处理下一条无需经过前一条的所有字段；保留独立的正式入库确认。

### 3. 首页成为继续工作的入口，统一数量口径

观察：首页显示“待提炼材料 2 份”，队列显示“待提炼 0、待确认 1、未完成任务 1”。源码说明两处“待提炼”的统计来源不同。首页当前将大块空间交给牌堆，已有候选和待恢复任务没有成为主要入口。

- 定位：`src/client/pages/DashboardPage.tsx:147`；`src/server/services/extraction-queue-service.ts:104`；`src/client/pages/QueuePage.tsx:244`。
- 建议：使用统一的任务阶段和统计来源；首页优先给出“继续审阅”“处理未完成任务”“整理新收件”等与真实状态一致的入口。
- 牌堆保留为待办材料浏览；已有结果直接进入审阅，避免统一叫“开始提炼”。总数与已加载数分开。
- 有待恢复操作时，导航和首页给出数量；无异常时保持安静。
- 验收：同名状态跨页面数量一致；从首页一次点击回到待完成的实际任务。

## 第二轮：提高连续使用效率

### 4. 给实体浏览补上快速查找方式

观察：档案库每次进入均需要开柜后才能搜索。知识以大纸页网格展示；档案输入后自动搜索，知识搜索需要提交，目录搜索的范围说明较弱。

- 定位：`src/client/components/library/ArchiveVault.tsx:15`；`src/client/pages/LibraryPage.tsx:98`；`src/client/pages/KnowledgeCabinetPage.tsx:154`、`:182`；`src/client/styles/knowledge-cabinet.css:84`。
- 建议：保留实体入口，增加直接搜索和“继续上次调阅”；打开收藏册后提供纸页/紧凑目录切换。
- 统一搜索触发方式：输入短暂防抖，Enter 立即提交；明确“当前目录 / 全库”，空结果提供扩大范围入口。
- 验收：已知标题可以直接找到；返回目录保留筛选和位置；无需遍历柜门、分类、子目录才能检索。

### 5. 提高阅读优先级和视觉清晰度

观察：多个页面常显工程信息，如“YAML 召回字段”“索引 V61”“原文版本”；不少辅助文字和操作为 10–12px。档案原文用 `<pre>` 展示完整 Markdown，队列却排版显示，同一资料的阅读体验不一致。

- 定位：`src/client/pages/LibraryPage.tsx:63`；`src/client/pages/KnowledgeCabinetPage.tsx:150`；`src/client/styles/queue-drawer-workspace.css:19`。
- 建议：保留黑银容器材质，阅读区采用安静背景和更亮的正文；正文可从 15–17px、行距 1.7–1.9 试起，核心操作使用清楚的中文标签。
- 常显“已连接”“正在保存”“等待审阅”等直接影响用户判断的信息；模型、版本和文件校验信息放进详情。
- 原文默认排版阅读，保留查看 Markdown/YAML 的入口；不改原始文件。
- 普通文本按 4.5:1、较大文本按 3:1 检查对比度。这是后续验收基线，本次未断言现有界面全部达标或不达标。依据：[WCAG 对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum)。

### 6. 缩短重复动效，减少布局变化

观察：抽屉配置为 720ms，档案柜进入可操作状态等待 680ms，合柜为 560ms。已经支持系统减少动态效果。仅凭这些数值不能断言存在掉帧，但重复操作的等待可以优化。

- 定位：`src/client/styles/queue-cabinet.css:2`；`src/client/components/library/ArchiveVault.tsx:23`。
- 建议试验值：按下反馈立即出现；常规按钮/选中变化约 120–180ms，面板切换 180–240ms，实体开合 300–450ms；首次开场可保留更完整动效。
- 异步读取与开合同时开始；局部刷新保留旧内容、焦点和滚动位置，不重新播放开场。
- 先确认布局变化发生在哪里，再针对实际瓶颈优化；不要仅凭 CSS 数量判断性能。
- 验收：连续开合、快速切换、搜索、打开问问时不误触、不跳走、不丢位置；另做真实设备帧率测量。

### 7. 每次完成都接上下一步，AI 上下文明确可见

观察：归档成功反馈主要是状态和路径；入库回执提供打开知识、返回原资料。问问会按当前页面带入资料，但同一对话中每条消息没有记录当时可见的范围标记。

- 定位：`src/client/pages/IntakePage.tsx:146`；`src/client/pages/queue/CandidateReview.tsx:298`；`src/client/components/assistant/AssistantPanel.tsx:164`、`:251`。
- 建议：归档后提供“提炼这份 / 继续整理”，入库后提供“使用这篇知识 / 处理下一份”。这些按钮进入下一步界面，由用户决定发送和保存。
- 问问输入区和消息标出“仅《当前资料》”或“整个大脑”；切换资料后明确本轮上下文变化。
- 有价值的后续能力：对选中段落解释、比较候选与已有知识、把已选知识用于文章或脚本大纲。先呈现引用与拟保存结果，再由用户确认。

## 后续能力的推荐次序

1. **全局搜索 / Cmd+K**：跨原始资料与知识检索、最近访问、跳转操作，优先解决“我记得有这段内容，在哪里”。
2. **继续工作与最近使用**：恢复上次资料、候选位置、搜索条件；提供可主动清除的最近记录。
3. **知识复用工作区**：选几篇知识，带来源形成选题、提纲、脚本或方法清单；保持产物预览和人工保存。

第一轮不建议同时扩展复杂知识图谱、更多模型切换和更多装饰动效。先让审阅、查找和继续工作形成稳定的主流程，再判断新增能力是否真的减少用户操作。

## 验收方法

用三项真实任务对照优化前后：继续审阅现有 4 条候选、从档案找到一份已知资料、用已有知识回答一个问题。记录定位下一步的时间、点击数、往返滚动、范围判断错误和未完成退出率。以上是建议测量项，本次没有声称获得量化提升。

## 补充评审：问问 AI

本次查看了实际首屏、历史列表、已有提炼对话，以及“审阅知识候选”进入工作区的过程；没有发送新问题或调用真实模型。以下区分历史输出、当前实现和新增建议。

### 应保留的基础

“问问”的名称、眼睛标识和侧栏入口已经统一；已有模型选择、资料范围、历史对话、来源链接、候选审阅入口、停止回答、失败重试，以及关闭面板后继续执行。用户向上翻阅时也会停止自动跟随输出。下一轮重点是让这些能力更好地服务阅读与整理。

### 优先级 1：统一结果承诺与真实操作

实测历史对话中，提炼回复写着可以说“入库”或“入库 1、3”来保存，同时显示“审阅知识候选”按钮。当前系统提示和工具契约却明确要求在审阅界面确认，AI 工具没有正式入库动作。这是已保存的历史回答与当前可用操作不一致，不代表本次复现了新模型输出。

- 依据：`src/server/assistant/service.ts:11`；`src/server/assistant/brain-tools.ts:138`；`src/client/components/assistant/AssistantPanel.tsx:255`。
- 建议：工具成功后由应用生成任务卡，明确显示资料标题、候选数量、“待审阅”和“打开审阅”；正文只保留摘要，完整候选按需展开。任务状态来自实际运行与入库回执，避免仅以模型措辞判断是否完成。
- 用户在聊天里要求入库时，定位并打开对应批次的审阅流程；待未来有完整预览与确认机制时，再讨论聊天内确认保存。
- 验收：用户只看结果卡就能判断完成的是生成、候选保存还是正式入库；不会被引导执行不存在的聊天命令。

### 优先级 1：资料上下文显式、稳定

当前发送从页面 URL 取资料路径；恢复历史对话时只恢复范围选项，后续请求仍使用正在浏览的页面路径。会话仅保存最新 scope/contextPath，消息本身没有范围快照。“当前资料”限制的是本轮工具读取，已有对话文字仍可能包含此前资料信息，界面不应暗示历史内容被隔离。

- 依据：`src/client/components/assistant/AssistantPanel.tsx:164`、`:185`、`:265`；`src/server/assistant/service.ts:79`、`:117`；`src/shared/api/assistant.ts:8`。
- 建议：输入框上方显示可读资料卡，如“本轮检索：仅《泛流量与精准流量》”；允许固定资料或主动改用当前页。每条问题保留当时的资料范围，恢复历史时显示该对话原来的资料。
- 后续增加选中段落提问和多篇资料选择，作为明确的新上下文能力实现，不能仅靠改标签。打开候选时需进一步区分“原文”“已保存候选”和“当前尚未提交的修改”。
- 验收：从 A 文档切到 B，或在 B 页面恢复 A 的对话，用户发出下一条问题前都能确认使用哪份材料。

### 优先级 1：答案引用能快速核对

目前来源有 S1 编号、标题和整篇文档链接；正文由通用 Markdown 渲染，没有专门的引用锚点与证据预览。搜索命中的文档也会进入来源列表，因此“参考资料”列表不等于实际使用过的正文证据。

- 依据：`src/client/components/assistant/AssistantPanel.tsx:253`；`src/client/components/SafeMarkdown.tsx:56`；`src/server/assistant/brain-tools.ts:49`、`:74`、`:113`。
- 建议：观点附近提供引用入口，点击先展开原文片段，再可定位完整资料；区分“找到的相关资料”和“本回答使用的证据”。片段、位置与版本需要后端随引用记录，不能由前端根据编号猜测。
- 验收：从一句结论到支持它的原文片段只需一次点击，返回后保留答案阅读位置。

### 优先级 2：按任务组织入口，减少参数占位

首屏常显服务、模型和思考强度两行设置，默认欢迎语只针对是否有当前资料变化一个问题。当前检查窗口宽 1270px，430px 的 AI 面板与 230px 导航同时出现，主工作区约剩 600px；已有 360–600px 调宽，但没有专注展开入口。

- 依据：`src/client/components/assistant/AssistantPanel.tsx:222`、`:236`、`:251`；`src/client/styles/assistant.css:11`。
- 建议：模型设置压成一行可展开控制，保留清楚的当前模型与连接状态。资料页推荐“解释这篇 / 提炼候选”；审阅页在支持候选上下文后推荐“核对依据 / 与已有知识比较”；知识页推荐“举个应用例子 / 用它写提纲”。推荐语先填入输入框供用户调整，沿用已有行为。
- 需要同步校正首屏“我最近收藏了哪些资料？”：当前原始资料工具要求非空标题关键词，且按路径合并排序，没有最近收藏列表或时间排序能力（`src/server/assistant/brain-tools.ts:99`）。应先换成已支持的主题检索问题，或补齐最近收藏工具后再保留该入口；本次未发送这个问题，不能断言实际每次回答均失败。
- 保留侧栏用于随手提问，增加“展开工作区”用于长文、表格和多来源对照；展开与收起保留输入、引用和滚动位置。
- 验收：用户进入资料页即可发现对应任务入口；打开 AI 后仍能舒适阅读正文和操作候选。

### 优先级 2：让等待和连续使用更顺畅

已有真实活动信息、停止回答和安全重试，进度目前以最新一句活动文字显示；历史以问题标题、日期和模型呈现。输入框固定三行，长问题没有随内容自动增高。

- 依据：`src/client/components/assistant/AssistantPanel.tsx:143`、`:234`、`:250`、`:257`、`:266`；`src/server/assistant/deepseek-adapter.ts:107`。
- 建议：把真实事件汇成“查找资料 → 阅读依据 → 整理回答/候选”的简短阶段记录；长等待显示已耗时与已完成步骤，不使用虚构百分比。用户向上阅读时出现“有新内容”入口。输入区自动增高到合理上限。
- 回答增加复制与选段追问；历史按主题或关联资料检索，提供“继续上次对话”。把回答转为候选或加入草稿需要新增明确的产物与预览流程。
- 后续验收覆盖长回答、停止后续问、连接中断后恢复、引用往返和历史对话切换。本轮未做流式延迟或帧率测量。

建议首先落地任务结果卡、资料范围卡和引用预览，再处理布局、历史检索和知识复用。期望的连续体验是：打开资料 → 选中一段提问 → 核对带来源的解释 → 生成候选 → 进入审阅 → 回到对话查看真实处理状态。

设计依据补充：清楚呈现系统能力、提供与当前任务相关的信息、解释系统行为和记住近期交互，符合 [Microsoft Research 的人机 AI 交互指南](https://www.microsoft.com/en-us/research/blog/guidelines-for-human-ai-interaction-design/)。具体取舍仍需以上真实任务验证。
