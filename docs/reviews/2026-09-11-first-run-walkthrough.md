# 首次使用核心任务走查 · 2026-09-11

走查对象：最佳拍档个人 macOS 桌面 App（原小兆大脑内部技术标识，开发版与 arm64 打包版），源码工作树 `desktop-read`。

走查问题：一个第一次打开、没有任何配置、不了解内部术语的用户，能否不查 README，独立把一份资料变成第一次可使用的知识结果？

## 先给结论

在隔离的临时大脑和临时 `userData` 中，当前版本已经能走通这条最短闭环：

`启动并连接大脑 → 带入一份资料 → 预览并确认归档 → 配置模型 → 预览并确认发送 → 等待结果 → 审阅候选 → 预览并确认入库 → 打开知识并回到原文`。

开发版和打包版均通过了零配置入口走查；收件箱归档、提炼、候选审阅/入库和重启恢复也有独立的隔离 GUI 验收。为降低首次理解成本，本轮只做了五处最小改动：

1. 首页把产品用途和“待提炼”说清楚；
2. 有待处理资料但未配置模型时，首页给出一次点击可达的设置提示；
3. 首页资料牌堆为空时，提供去收件箱的下一步；
4. 收件箱空态说明资料来自浏览器剪辑插件，同时说明当前版本可直接导入文件或粘贴文本；
5. 整理单明确提示未归档字段只保留在当前页面，提醒用户先预览并确认。

2026-09-13 发布前收口又补上了首次没有可用大脑时的“创建我的大脑”分支：用户选择保存位置后，应用只创建最小目录和初始规则文件；已有大脑、取消、目录碰撞和创建失败路径保持可恢复。设置单元测试 11 项通过，最新源码已重新构建并打包。

2026-09-13 品牌与发布收口：页面、窗口、设置页、AI 提示和新建规则说明统一使用“最佳拍档”；白底双人图标已接入网页 favicon 与 macOS 打包，`最佳拍档.app` 内的图标资源与源码 `.icns` 哈希一致。为兼容已配置用户，Electron 的旧 `小兆大脑` 数据目录仍保留，不改变内部 `xiaozhao-*` 技术标识。

这不是用户研究，也不等于用户已经认可。真实 DeepSeek 账号、正常首次启动的原生文件夹选择框、真实用户对术语的理解，以及跨页面/重启时未提交的收件箱字段，仍需人工或后续专项验证。全程没有清空真实账号或配置，没有真实授权、对外发送或支付。

## AI 侧本轮最小优化

在不改变“用户确认后才发送、候选确认后才入库”的设计前提下，本轮补了三处可恢复性和可核对性：

1. **错误动作对齐【源码确认/已观察】**：DeepSeek HTTP 402 现在明确显示余额不足；密钥失败提供“去设置更新密钥”，网络/限流/超时仍提供重新预览。不会自动重发。
2. **阅读判断连续【源码确认/已观察】**：失败或取消后重试会携带原来的“未看/已看”选择，下一次预览仍使用同一判断；用户可以继续修改。
3. **发送范围透明【源码确认/已观察】**：发送预览显示 JSON 消息的近似字节数和 500 KB 上限；原文、规则或目录超限时提示“尚未发送”及拆分/减少范围的下一步。候选阅读区显示原文逐字摘录数量；没有摘录时明确提示打开原文依据核对。

这些改动解决的是流程反馈，不等于真实模型质量优化。真实模型输出、费用和不同资料类型的效果仍【未验证】。

1. `/` 大脑总览：理解用途、查看继续工作状态、去收件箱或提炼队列。
2. `/intake` 收件箱：读取浏览器剪辑插件包；当前桌面运行时也提供文件选择和粘贴文本，先暂存，再预览、确认归档。

4. `/extractions/:id` 提炼工作区：核对原文、阅读状态和规则，查看实际发送预览，明确确认后才调用模型；等待、失败、取消和重试均留在同一任务。

6. 入库预览与确认：查看知识文件和原资料状态变化，明确确认后写入。
7. `/knowledge` 知识库：打开知识纸页；从来源与关联知识展开原始资料，形成结果回路。
8. `/library` 档案库、`/operations` 操作与恢复、`/trash` 回收站：用于浏览、恢复和异常处理，不是首次完成任务的必经步骤。
9. `/settings` 设置：大脑文件夹、DeepSeek、运行状态、待确认资料和高级诊断。

### 设计阶段模块的逐步走查与验收要求

对仍处于“设计/规划”或“已确认、尚未纳入当前交付”的模块，本轮不把静态方案当成已完成，而是沿用同一套验收要求，供实现时逐步走查：

1. 入口先用普通语言说明要完成的结果和下一步，不要求用户先学内部术语。
2. 运行前集中列出当前可判断的缺项，按依赖顺序补齐；非必要设置不能变成首屏必填。
3. 返回、跳过、失败和重试保留当前任务与已填内容；若只能保留在当前页面，要明确写出边界。
4. 等待状态说明正在读取、发送、写入或核验什么；失败给原因和可执行动作；成功给结果、位置和来源。
5. 每一个会外发、写入、删除或改变权限的动作都要有独立预览与明确确认，并能在隔离数据中重跑。

在模块真正接入路由和数据后，才将“设计要求”升级为“已观察”；没有真人试用时，验收通过只表示自动化/代码证据通过。

## 核心任务与最短可用流程

核心任务不是“配置所有设置”，而是：**把一份收藏的资料变成可复用的知识，并能打开知识、回到原文依据。**

| 步骤 | 用户处境与操作 | 应看到的反馈 | 完成判据 |
| --- | --- | --- | --- |
| 1. 连接大脑 | 第一次启动；接受默认路径或选择完整的大脑文件夹。 | 选择框说明“完整的大脑文件夹”；无效选择说明缺少什么并可重新选择；取消不改变原设置。 | 主界面打开，原始资料未被移动。 |
| 2. 理解入口 | 看首页，不知道“提炼”是什么意思。 | 页面说明“把收藏的资料变成可复用的知识”；“待提炼”旁说明“还没有生成知识候选”。 | 能说出产品用途和当前待处理状态。 |
| 3. 带入资料 | 选择“整理新收件”；打开邮筒。可由插件产生资料，也可在上方导入文件/粘贴文本。 | 空态说明来源和下一步；有资料时显示缺少标题、平台、日期或主文件。 | 找到一份可整理资料，不靠报错猜入口。 |
| 4. 归档 | 核对必填标题、来源平台、采集日期和主 Markdown；作者、链接可留空；点击预览，再确认归档。 | 预览展示真实目标路径、YAML 与原文；确认后显示“归档完成”、提炼入口和已归档资料入口。 | 原件进入对应档案位置，原文/附件保真，知识仍为“未提炼”。 |
| 5. 准备模型 | 点击“提炼这份”；若没有密钥，去设置保存 DeepSeek API Key。 | 提炼页明确“不发送任何资料”；设置页说明本机加密保存，保存不等于远端验证；失败可保留输入重试。 | 用户明确授权外发和可能费用后，密钥保存在本机。 |
| 6. 发送与等待 | 选择“未看/看过”，展开实际发送内容，点击“确认发送并提炼”。 | 显示正在读取/提交/生成；允许离开后回来，失败给普通语言和重试；不展示伪造进度。 | 获得保存到本机的导读与候选，原资料未被模型静默改写。 |

| 8. 找回结果 | 点击“打开知识”，再展开来源。 | 知识正文可读，来源链接回到原始资料；已处理结果可再次打开。 | 第一次有效结果可使用，且能核对来源。 |

| --- | --- | --- |
| 选择一个有效的大脑文件夹 | 这是本地资料和知识的真实数据范围，涉及读取权限与文件位置。 | 启动时；默认路径无效才要求选择。 |
| 是否保存 DeepSeek API Key | 模型会接收选定资料，可能产生费用；必须由用户决定是否使用。 | 真正开始提炼前，不阻挡只读浏览或先归档。 |
| 是否确认归档 | 会把收件包写入正式档案位置。 | 预览后。 |
| 是否确认发送 | 会把预览中的资料发送到 DeepSeek。 | 发送预览后。 |
| 每条候选的保留、放弃或稍后处理，以及新建/合并 | 这些是知识取舍，不能由数量或相似度代替。 | 候选审阅时。 |
| 是否确认入库 | 会写知识 Markdown、原资料状态和来源回链。 | 批次预览后。 |

### 可以用合理默认值

| 内容 | 当前默认 | 允许的原因 |
| --- | --- | --- |
| 大脑候选位置 | `~/我的大脑` | 常见默认路径；无效时明确进入选择/重试。 |
| 阅读状态 | `未看` | 不冒充用户已读；用户可在提炼前改为“看过”。 |
| 插件采集日期 | 使用 `clipped` 映射；`published` 只保留发布时间含义。 | 不丢原始字段，预览可核对。 |
| 归档目录 | 按平台和月份生成真实目标路径。 | 避免首次要求用户理解目录规则。 |
| 模型 | 当前默认 `deepseek-v4-pro`。 | 首次目标是得到结果，不要求先做模型选择。 |
| 高级诊断 | 默认折叠。 | 工程信息不应成为首次使用门槛。 |

### 可以稍后补充

- 作者、原始链接（界面已标注“可留空”）。
- 主题、关键词、召回字段和候选正文的进一步编辑。
- 设置页“待确认资料”和“高级诊断”中的结构/兼容问题。
- 保存密钥后的独立连接验证；“已保存”不伪装成“已验证”。
- 在 Finder/Obsidian 中打开原文，以及回收、恢复、历史操作等非核心动作。

## 问题清单（按对核心任务的影响排序）

### P1 · 空收件箱没有告诉用户资料从哪里来（已修正）

- **用户处境**：第一次打开，想把自己的收藏放进大脑，但还没有连接插件或导入文件。
- **操作**：首页点击“整理新收件”，进入收件箱，点击“打开收件箱”。
- **修复前看到的反馈【已观察/源码确认】**：空托盘只说“收件箱是空的”；归档历史只说完成后会保留，未说明浏览器剪辑插件或直接导入入口。旧静态走查因此把“手动放文件并不支持”写成了过强结论；当前源码实际已经有 `IntakeFileImport`，该结论已纠正。
- **为什么会卡住【设计推断】**：用户无法判断下一步是安装/使用插件、等待同步，还是在 App 内选择文件；这是闭环的第一个动作，误判会让后续流程完全无法开始。
- **最小修改**：在邮筒闭合态和托盘空态各补一句条件式来源说明：有 attachments 能力时同时提到“浏览器剪辑插件”和“上方选择文件或粘贴文本”，否则只说明插件来源。不新增引导页、不新增必填项。
- **修复后反馈【已观察】**：隔离开发版和打包版均看到“浏览器剪辑插件保存的收藏”和“上方选择文件或粘贴文本”。
- **可观察验收**：零配置用户在空态能说出至少一种可用下一步，并能在不查 README 的情况下找到该入口。永久断言见 `tests/electron/first-run-walkthrough.test.ts` 与 `tests/component/intake-page.test.tsx`。
- **状态**：已修正；插件归档 GUI 已观察，直接导入完整 GUI 闭环仍【未验证】。

### P2 · 首页用途和“待提炼”术语不够直白（已修正）

- **用户处境**：刚打开首页，不认识“提炼、候选、入库”等系统词。
- **操作**：只看首页的“继续工作”和资料牌堆。
- **修复前看到的反馈【已观察/源码确认】**：主要是品牌 slogan、四个数量和内部状态名；用户需要先理解系统词，才能知道为何要点队列或收件箱。
- **为什么会卡住【设计推断】**：不能从“待提炼 0”推断“下一步是导入资料”，也不能判断“候选”是否已经是正式知识。
- **最小修改**：把总览页描述改为“把收藏的资料变成可复用的知识”；在“继续工作”区补“‘待提炼’表示还没有生成知识候选”。只改一行用途说明和一行短语消歧，不重做布局。
- **修复后反馈【已观察】**：首页首屏出现完整用途说明和术语解释，组件及开发/打包 first-run 断言通过。
- **可观察验收**：新用户看完首页能复述产品用途，并能解释“待提炼”不是“已经有知识”。
- **状态**：已修正；真人理解度仍【未验证】。

### P3 · 可判断的模型缺项没有在开始前集中露出（已修正）

- **用户处境**：已经有一份待提炼资料，但还没有 DeepSeek 密钥；可能先花时间整理完才发现不能运行。
- **操作**：从首页查看继续工作区。
- **修复前看到的反馈【已观察/源码确认】**：首页不显示模型状态，进入具体提炼页后才出现“先配置 DeepSeek 密钥”。
- **为什么会卡住【设计推断】**：用户不能在投入归档/整理前知道当前还缺什么；但把密钥强制放到首次启动又会阻挡只读浏览和先归档。
- **最小修改**：仅在“存在待提炼资料 + 模型未配置”时，在首页显示“开始提炼前需要配置 DeepSeek 密钥 · 去设置”，点击直达 `/settings`；没有待提炼资料或已经配置时不显示。
- **修复后反馈【已观察】**：隔离零配置 fixture 有待提炼资料时提示可见并可一次点击到 DeepSeek 设置；已配置/空队列 fixture 不出现提示。
- **可观察验收**：提示不把模型设置变成启动必填项，且用户在第一次点“开始提炼”前已能看到缺项和去处。
- **状态**：已修正；真实余额/网络验证仍【未验证】。

### P4 · 没有资料时只说“没有”，没有下一步（已修正）

- **用户处境**：新大脑为空，或已有资料都已处理完；首页牌堆没有卡片。
- **操作**：查看首页“待处理资料”。
- **修复前看到的反馈【已观察/源码确认】**：只显示“暂无待提炼材料”。
- **为什么会卡住【设计推断】**：用户不知道应该去收件箱、档案库，还是等待插件；空状态没有把用户送回核心任务入口。
- **最小修改**：在牌堆空态下增加一个轻量链接“去收件箱整理新收件”，指向 `/intake`。不自动打开抽屉，也不增加教程。
- **修复后反馈【已观察】**：空牌堆显示可点击的收件箱出口，组件测试通过。
- **可观察验收**：新用户能从空首页一步到收件箱；已处理资料仍保持空态，不被制造成假任务。
- **状态**：已修正；真人是否选择该出口【未验证】。

### P5 · 正常首次启动的原生选择框是否让人看懂（创建入口已补，理解度未验证）

- **用户处境**：没有有效的默认 `~/我的大脑`，首次启动弹出系统文件夹选择框。
- **操作**：选择、取消或选择一个不完整目录。
- **应该看到的反馈【源码确认】**：先看到“创建我的大脑 / 选择已有文件夹 / 取消”；创建分支说明只建立初始目录和规则文件，再让用户选择保存位置。已有目录分支仍说明选择完整目录；无效目录提示缺少规则/图书馆/知识库/大讲堂，可“重新选择/取消”；取消不改变配置。
- **可能卡住的原因【设计推断】**：“大脑文件夹”是产品术语，系统选择框本身不会展示内部结构含义。
- **最小修改**：已补首次创建分支和保存位置的普通语言说明；仍需在隔离测试大脑上进行一次真人观察，若仍不懂，只补一行说明，不新增设置步骤。
- **可观察验收**：真人在不查项目文档的情况下，能选择含四个目录和规则文件的文件夹；取消后能知道应用没有启动且资料未动。
- **状态**：创建/已有/取消分流已实现；真人对系统选择框和“保存位置”的理解仍未验证，不能写成用户已认可。

### P6 · 收件箱未提交字段的持久化边界需明确（边界提示已补，持久化仍有限）

- **用户处境**：已在整理单里补了标题，随后合上收件箱、刷新、切换页面或重启；也可能在归档/读取失败后重试。
- **已观察的反馈**：当前页面内合箱、重开、切换信封会保留编辑字段；连接失败提示“本地连接中断”，保留字段并可刷新；候选编辑草稿保存到本机，重启后可恢复；提炼任务和批次有同一 ID 的查询/重试入口。
- **未承诺的反馈【源码确认】**：收件箱编辑字段存于当前页面的内存草稿，README 明确写着不代表跨页面或重启持久保存；直接粘贴文本在提交成功前也不是正式资料。
- **为什么会卡住【设计推断】**：用户若误以为“已填”就是永久保存，离开页面可能丢失未归档信息；这属于可预见的边界，不应让用户靠失败后猜测。
- **最小修改**：不把临时字段升级为新的数据库对象；在整理单步骤条下补充“尚未归档的整理内容只保留在当前页面；离开前请先预览并确认归档”。连接失败和已提交批次继续沿用现有同一编号查询/重试。
- **修复后反馈【已观察】**：打开整理单即可看到边界提示；编辑、合上收件箱、失败重试的既有当前页保留行为不变。
- **可观察验收**：用户在填写前能看到保存边界；当前页面内返回、失败重试不会丢已填字段；若要离开页面，能看到是否已归档以及是否需要重新填写。
- **状态**：边界提示已修正；跨页面/重启的未提交收件箱字段仍未做真人确认，也未承诺持久保存。

## 已有设计中应保留的部分

- 模型密钥在需要它的步骤才出现；保存密钥不会自动发送测试消息，单独验证才会产生固定测试请求。
- 归档和模型发送都有完整预览与独立确认，预览不等于写入/外发。
- 提炼等待显示正在读取、提交或生成，允许离开后回到同一任务；失败给出普通语言和重试，不伪造进度。
- 零候选明确说“不需要为了数量强行入库”，不把模型结果数量变成目标。
- 候选保存到本机草稿不冒充正式知识；入库前显示文件变化，确认后才写入。
- 原文、附件、知识和来源回链有可查入口；成功后不是只给一条“完成”提示。
- 设置页的待确认资料和高级诊断默认折叠，工程术语不挤进首次使用主视线。
- 真实大脑只读或恢复检查，所有自动写入、崩溃、中断和冲突验证使用独立临时库。

## 仍未验证，不能当成用户认可

1. 真人第一次看到原生文件夹选择框时是否理解“大脑文件夹”。
2. 真人在 1280/1440/窄窗口首屏是否同时读懂用途、数量、空态和下一步。
3. 插件尚未安装、插件保存失败或目录权限不足时，用户是否能从普通语言得到可执行处理方式；当前没有在 App 内新增插件获取流程。
4. 从零配置通过“选择文件/粘贴文本”而不是插件，完整走到第一次知识结果的独立 GUI 路径。
5. 真实 DeepSeek 密钥、网络、余额、费用、模型输出质量和服务端错误文案。
6. 用户跨页面或重启前是否会期待未提交的收件箱字段仍在；当前已有边界提示和代码/组件级证据，但没有真人观察，也未承诺跨页面或重启持久保存。
7. 本轮自动化验收证明可操作性，不证明真实用户已经认可流程或文案。
8. “最佳拍档”公开分发的 DMG、Developer ID 签名、公证和 Gatekeeper 安装体验仍未完成；当前打包版仅适合本机验收。

## 后续加功能时的复查规则

每次新增入口、前置条件、权限、状态或异步任务，都要从零配置核心任务重新检查：

1. 先把准备条件归入“必须由用户授权或决定 / 可用合理默认值 / 可稍后补充”，再决定出现步骤；不要把所有设置变成首次使用必填。
2. 新术语第一次出现时，在界面旁用一句普通话消歧；README 不能代替界面说明。
3. 空状态必须给出明确下一步去处；没有资料不等于没有任务出口。
4. 运行前集中呈现当前已经能判断的缺项；有依赖的准备项按顺序出现，不能让用户靠反复运行和报错发现要求。
5. 返回、跳过非必填项、连接失败和重试必须保留当前任务与已填内容；若只保证当前页面内，界面要明说持久化边界。
6. 等待要说明正在做什么；失败要说明原因和可执行下一步；成功要提供结果和来源入口。
7. 工程诊断默认放在“高级诊断”折叠区，不为了引导而增加引导。
8. 每次改动核心入口、权限、外发、写入或结果回路后，重跑 `tests/electron/first-run-walkthrough.test.ts`，再在隔离临时大脑中复核首次使用和已配置用户流程；不要用真实账号制造首次使用。

相关永久回归：`tests/electron/first-run-walkthrough.test.ts`。
